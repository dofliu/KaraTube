# KaraTube 使用說明書

本文件說明 KaraTube 的安裝、啟動與所有功能的操作方式。

---

## 1. 安裝與啟動

### 環境需求

| 項目 | 需求 |
|---|---|
| Python | 3.10 以上 |
| FFmpeg | 系統需能直接呼叫 `ffmpeg` |
| GPU | NVIDIA GPU（建議，可大幅加速 AI 分離與語音識別；無 GPU 亦可運作，速度較慢） |
| 瀏覽器 | Chrome / Edge（需支援 Web Audio API） |

### 安裝

```bash
pip install -r requirements.txt
```

> 開發者只想跑測試的話，安裝 `requirements-dev.txt` 即可（不含 torch / demucs 等大型依賴）。

### 啟動

```bash
python run.py
```

啟動後自動開啟：

- **點歌控制台**：`http://localhost:8080`
- **舞台大螢幕**：`http://localhost:8080/player.html`

建議雙螢幕配置：筆電螢幕開點歌台，外接電視/投影機全螢幕開舞台頁。

## 2. 點歌

### 搜尋點歌

1. 在點歌台上方搜尋框輸入 **歌名、歌手**，或直接貼上 **YouTube / YouTube Music 網址**。
2. 每張歌卡有兩個按鈕：
   - **🎤 點歌**：加到佇列最後。
   - **⚡ 插播**：插到佇列最前面，下一首就唱。
3. 第一次點的歌會自動走後端流水線：下載 MV → AI 人聲伴奏分離 → 歌詞對齊 → 音高抽取，佇列中會顯示處理進度。點過的歌會快取，第二次秒播。

### 曲庫分頁

搜尋框下方有七個分頁：

- **📚 快取歌曲**：本機已處理完成的歌，點了免等待秒播。
- **🎼 分類瀏覽**：依語言別與歌手分類點歌（見下節）。
- **🆕 新歌推薦**：最近加入曲庫的新歌，加上依你的點唱紀錄產生的推薦歌單（見下節）。
- **⭐ 我的最愛**：收藏的常唱歌曲（見下節）。
- **🏆 點唱排行**：按實際上台演唱次數排序的熱門排行，顯示次數與最近演唱日期。
- **🕘 已唱歷史**：最近實際演唱過的歌（最新在前），標示演唱時間，一鍵再點。分頁上方會顯示「今天唱了幾首」。
- **🗂️ 快取管理**：每首快取歌曲的磁碟用量與完整性，可刪除或重新處理（見下節）。

### 分類瀏覽（語言別 / 歌手）

「🎼 分類瀏覽」是商用點歌機的「分類點歌」：先縮小範圍，再從清單裡挑歌。

- **🌏 語言**：國語 / 台語 / 粵語 / 日語 / 韓語 / 英語 / 其他。
  只列出曲庫裡真的有歌的語言，每個標籤後面是首數。
- **🎤 歌手**：曲庫裡的歌手，歌多的排前面。歌手多的時候這一列可以往下捲。
- **↕️ 排序**：最新加入 / 最常點唱 / 歌名 / 歌手。
- 語言與歌手可以疊加（例如「台語」＋「江蕙」），按 **全部語言 / 全部歌手** 取消該項篩選。
- 歌卡左下角會標語言別，方便一眼分辨。

語言與歌手是伺服器自動判定的：語言看歌名、頻道名與歌詞（粵語、台語靠方言用字，
要出現兩種以上才算），歌手則從 YouTube 頻道名還原
（`周杰倫 - Topic` → `周杰倫`；頻道是唱片公司時改抓「歌手 - 歌名」的前半段）。
判定結果存在該首歌的 `metadata.json`，只算一次。

> 判錯了怎麼辦？分類只影響歌出現在哪個分頁，不影響演唱。
> 想改判可以到「🗂️ 快取管理」對該首歌按 **🔁 重新處理**（重跑後會重新判定），
> 或直接編輯 `cache/songs/<影片ID>/metadata.json` 裡的 `language` / `artist_name`。

### 新歌推薦（新歌榜 + 為你推薦）

「🆕 新歌推薦」分頁分成上下兩區：

- **🆕 新歌榜**：最近加入曲庫的歌，最新排最前面；14 天內加入的會標上 **NEW** 徽章。
- **💡 為你推薦**：依你的點唱紀錄推回「接下來唱什麼」，每張卡片都寫出推薦理由：
  - 「好久沒唱了，再來一次？」—— 唱過兩次以上但最近沒再點的老歌。
  - 「你唱過 XXX，這首還沒唱過」—— 最近唱過的歌手的其他歌。
  - 「剛加入曲庫，還沒開嗓過」—— 曲庫裡從沒唱過的歌。

### 我的最愛（收藏）

- 每張歌卡右上角有星星按鈕：**☆ 未收藏 / ⭐ 已收藏**，點一下切換。
- 收藏在「⭐ 我的最愛」分頁集中管理，最新收藏排最前面，一鍵再點歌。
- 收藏存在 `cache/favorites.json`，重開機不會消失。

### 多人包廂暱稱（誰點的歌）

- 點歌台（含每支掃碼連入的手機）右上角有 **👤 設定暱稱** 按鈕，輸入自己的暱稱。
- 設定後點的每一首歌，佇列上都會掛 **👤 暱稱** 標籤，舞台片頭卡也會顯示「點歌：XXX」。
- 暱稱存在各裝置自己的瀏覽器（localStorage），每個人只要設定一次；不設定也能照常點歌，只是不顯示標籤。

### 佇列管理

- 右側「點歌排隊佇列」顯示待唱清單與每首歌的處理狀態，以及是誰點的（有設定暱稱時）。
- **拖曳排序**：按住每首歌左側的 **⠿** 把手上下拖曳即可調整演唱順序，
  桌機滑鼠與手機觸控都支援，放手後所有裝置的佇列即時同步。
  （佇列只有一首歌時不顯示把手 —— 沒得排。）
- 點 **✕** 可把歌從佇列移除。
- 處理失敗的歌（紅色「● 處理失敗」）會多一顆 **🔁** 重試按鈕 ——
  網路斷線、影片暫時抓不到之類的暫時性錯誤，重跑一次通常就過了，不用重新搜尋點歌。
- 佇列裡的歌唱完會自動接下一首就緒的歌。

### 快取管理

「🗂️ 快取管理」分頁是發布機台的日常維運入口：

- 分頁上方顯示 **快取幾首歌、共佔多少空間、磁碟還剩多少**。
- 每首歌一列，顯示磁碟用量與完整性徽章：
  - **完整**：四個必要檔案（伴奏、人聲、歌詞、metadata）都在，可直接點歌。
  - **不完整**：處理中斷或失敗的殘留（缺哪些檔案滑鼠移上去看得到），照樣佔磁碟。
- **🎤 點歌**：完整的歌直接排入佇列秒播。
- **🔁 重新處理**：砍掉現有快取、重跑整條流水線（下載 → AI 分離 → 字幕對齊 → 音高抽取）。
  字幕全歪、伴奏有雜音、檔案缺漏時用這顆。需要幾分鐘，完成後自動就緒。
- **🗑️ 刪除**：刪掉快取釋放磁碟空間，下次再點會重新處理。
- **演唱中或還在佇列裡的歌不能刪也不能重新處理**（會直接讓舞台斷片），先切歌或從佇列移除再操作。

### 已唱歷史

- 「🕘 已唱歷史」分頁記錄每一次實際上台的演唱（同一首唱三次就有三筆），排進佇列又被刪掉的不算。
- 卡片上顯示演唱時間（今天的顯示「今天 21:34」），點 **🎤 點歌** 即可再唱一次。
- 歷史存在 `cache/song_history.json`，保留最近 500 筆，重開機不會消失。

## 3. 演唱控制（底部控制列）

| 控制 | 說明 |
|---|---|
| 🔄 重唱 | 目前這首從頭再來 |
| ▶ / ⏸ | 播放 / 暫停 |
| ⏭ 切歌 | 跳到下一首 |
| 🎤 原唱/伴奏滑桿 | 0% = 純伴奏（KTV 模式），100% = 原唱導唱，中間無段調節 |
| 🎵 音樂 | 伴奏音量（不影響麥克風） |
| 🎙️ 麥克風 | 麥克風監聽音量，拉到 0 可立即止住嘯叫 |
| 進度條 | 點一下即可跳到該處播放；黃色區塊是目前圈起來的 A-B 練唱區間 |

## 4. 調音台（🎛️ 按鈕）

- **升降 Key**：♭ 降 / ♯ 升，範圍 -6 ~ +6 半音，「原」一鍵歸零。
- **快速調性（男調/女調）**：商用點歌機的一鍵變調 ——
  **♂ 男調** 一鍵降 4 個 Key（女歌男唱）、**♀ 女調** 一鍵升 4 個 Key（男歌女唱）、**原調** 回到原 Key。
  按了之後仍可用 ♭/♯ 微調；目前 Key 值所有裝置即時同步。
- **演唱模式**：
  - 🎧 **單人**：人聲不進喇叭，不可能回授，適合筆電內建麥克風。評分照常。
  - 🔊 **多人**：人聲外放，**務必使用外接喇叭**。
- **效果風格（一鍵套用）**：商用點歌機的三種現場感 ——
  **🚪 包廂**（標準 KTV 手感）、**🎭 劇場**（殘響厚一點、回音收斂）、
  **🏟️ 演唱會**（大空間、長回音）。按一顆就同時設定好殘響與回音四個參數，
  之後仍可用下面的滑桿微調（微調後按鈕熄燈，表示已離開預設值）。
  柔化（防嘯叫）是場地相依的設定，不跟著風格走。
- **麥克風效果**：柔化（壓高頻）、殘響（空間感）、回音音量、回音重複次數、回音間隔（80~600ms）各自獨立調整；**乾聲** 一鍵全關。
- **字幕同步**：±1 秒微調字幕時間（正值 = 字幕延後），用來補喇叭/藍牙輸出延遲。雙擊滑桿歸零。舞台端也可按 `←` `→`（Shift 微調 10ms、`0` 歸零）。
- **音準導唱線**：切換舞台頂部的音準線顯示（舞台端也可按 `P`）。
- **🔁 練唱模式（A-B 循環）**：見下一章。

## 4-1. 練唱模式（A-B 段落循環）

商用點歌機的「副歌重播」。在調音台的 **🔁 練唱模式** 區塊操作，
圈起來的區間是共享的 —— 包廂裡每台裝置看到的都一樣，舞台右下角會亮 🔁 徽章。

### 手動圈一段（A-B）

1. 歌播到想練的段落開頭，按 **A**。
2. 播到段落結尾，按 **B**。兩點都設好就**立刻開始循環**，唱到 B 點自動跳回 A 點。
3. 想停就按 **⏹ 停止循環**；要重圈按 **清除**。
4. A、B 按反了不用重來 —— 系統會自動對調。太短（不到 1 秒）的區間不會啟動循環。

### 一鍵副歌重唱

按 **副歌重唱**，系統會分析這首歌歌詞的重複結構，自動圈出副歌並開始循環，
同時跳到副歌開頭。找不到重複段落的歌（例如純演奏、歌詞沒抓到）會提示改用手動 A-B。

### 段落跳轉

練唱區塊下方會列出這首歌自動切好的段落：**前奏 / 主歌 1 / 副歌 1 / 間奏 1 / …／尾奏**。

- 點段落標籤 → 直接跳到那一段。
- 點段落右邊的 🔁 → 圈住那一段循環練唱。
- 底部的進度條也可以直接點一下跳過去。

### 備註

- 換下一首歌時 A-B 區間會自動清掉，不會帶到下一首。
- 跳轉不會沒收你已經唱到的分數；只有音準線上的舊軌跡會清掉（否則會畫出鬼影）。
- 開著循環時歌不會自然結束，也就不會出現唱畢結算 —— 練完記得先停止循環。

## 5. 系統設定（⚙️ 按鈕）

點歌台右上角的 **⚙️ 系統設定**。所有設定自動存進 `cache/settings.json`，重開機沿用。

### 🎚️ 開機預設調音

伺服器每次啟動時要套用的初始值：音樂／麥克風／導唱音量、升降 Key、
殘響、回音（音量／重複／間隔）、柔化、演唱模式、音準線顯示。

包廂調到滿意的手感之後把它設成預設，下次開機就不用再調一輪。
改完不想重開伺服器的話，按下方的 **⤵️ 套用預設到現在** 即可立刻生效。

### 🔊 自動音量平衡（EBU R128）

> 解決「上一首震耳欲聾、下一首要把音量轉到底才聽得到」。

- YouTube 上的來源響度差距很大：官方 MV 母帶常壓到 -8 LUFS，
  個人上傳的現場版可能只有 -22 LUFS —— 中間差了 14 dB。
- 每首歌在處理流水線的最後會量一次 **整合響度（integrated loudness，
  ITU-R BS.1770-4 的 K 加權 + 雙重閘門）**，把結果存進 metadata；
  播放時自動補到同一個目標響度，所以每首聽起來一樣大聲。
- **目標響度** 預設 -14 LUFS（串流平台通用值）。想更安靜就往負的調。
- 增益夾在 ±12 dB，而且會做峰值保護（拉完不超過 -1 dBFS），不會把歌拉到破音。
- 量不到響度的歌（檔案損壞、近乎靜音）一律 0 dB —— 寧可不動，也不要亂調。
- **啟用前就快取好的舊歌** 不用重跑流水線：第一次播放時會現場量一次並補寫回 metadata。

### 🎚️ 導唱自動淡出（Guide Vocal Auto-Ducking）

> 解決「導唱開著怕唱不出自己的味道，關掉又怕忘詞」。

- 導唱人聲不再只有開／關兩檔：**唱穩了它自己退到背景，走音或忘詞時立刻回來扶一把**，
  跟商用機的「導唱漸弱」是同一件事。
- **淡出深度** 決定最多壓多少：預設 60%（最低降到原本的 40%）。
  上限 95%，**永遠留一點導唱在背景當安全網**，不會整段消失。
- 退場是慢慢來的（約一兩秒），回來是立刻的（約 0.2 秒）—— 救援不能遲到。
- 命中率看的是最近約一句歌詞的長度，唱錯一兩個字不會把導唱整個叫回來；
  在門檻附近游移時維持現狀，不會忽大忽小。
- 每首歌開頭會先觀察 3 秒才可能開始退場（第一個音唱準不算穩定）。
- 前奏、間奏不作用；**把調音台的「導唱人聲」轉到 0（純伴奏）時整個功能自動停用**。
- 退場時舞台右下角會亮出 🎚️ **導唱自動淡出 XX%** 徽章，
  讓台上的人知道那是機器在讓路，不是設備出問題。

### 🗂️ 快取

- **快取上限**（GB，0 = 不限制）與 **自動清理最舊的歌**。
- 開啟後每處理完一首新歌就檢查一次，超過上限就從最舊的開始刪，
  **演唱中與還在佇列裡的歌絕對不刪**。
- 想手動挑著刪，用點歌台的「🗂️ 快取管理」分頁。

### 🤖 AI 模型

- **歌詞辨識模型**（Whisper：tiny ~ large-v3）與 **人聲分離模型**（Demucs）。
- 越大越準也越慢、越吃 VRAM。**模型在伺服器啟動時載入，改完要重開伺服器才生效**
  （設定頁下方會顯示目前實際運行中的模型與運算裝置）。

### 🖥️ 舞台演出

- 導唱片頭卡的開關與停留秒數、唱畢結算畫面的開關與停留秒數。
- 改完舞台端立刻套用，不用重開。關掉結算畫面時成績照樣記錄，只是不佔用畫面時間。

**♻️ 恢復原廠設定** 會把以上全部設回出廠值。

## 7. 手機點歌

1. 點歌台右上角點 **📱 手機點歌 QR**。
2. 手機相機掃描 QR Code（需與主機同一區域網路）。
3. 手機開啟的就是完整點歌台：點歌、插播、切歌、調音、音效全部可用，所有裝置狀態即時同步。

## 8. 舞台大螢幕

- 全螢幕 1080p MV 背景。
- **導唱片頭卡**：每首歌開始（含重唱）時，左下角亮出開場卡（預設 8 秒）——
  歌名、「演唱者：XXX」、以及點歌人暱稱（有設定時），如同商用點歌機的前奏提示。
  秒數與開關可在 **⚙️ 系統設定 → 舞台演出** 調整。
- 經典 KTV 雙行逐字變色字幕，3、2、1 倒數預備光點。
- 頂部音準導唱線 + 麥克風實時音高游標，即時 PERFECT / GREAT / GOOD 判定與 Combo。
- 快捷鍵：`←` `→` 字幕同步微調、`0` 同步歸零、`P` 切換音準線。

### 唱畢總評分結算

- 整首唱完，舞台自動亮出成績單：**總分**（滾動動畫）、**SSS~C 等級**、**音準率**、**最大 COMBO**。
- 下方顯示 **本曲個人最佳** 與 **擊敗全場 XX% 的演唱**；打破紀錄會顯示「🎉 刷新個人最佳！」。
- 結算畫面停留 9 秒（可在 **⚙️ 系統設定 → 舞台演出** 調整）後自動進下一首；**點一下畫面可直接跳過**。
- 沒人開口唱（純放歌）不會出結算畫面，直接接下一首。
- 隱藏音準線（`P`）時評分照樣進行，結算不受影響。
- 成績存在 `cache/score_history.json`；點歌台與手機端會同步收到「🏁 XXX：1234 分（S）」通知。

### 段落評分（哪一段唱得最好／最差）

結算畫面中間多一塊 **📊 段落表現**：

- 每一段（主歌 1、副歌 1、主歌 2…）一條長條，右邊標命中率百分比。
- 上方點名 **💯 最佳段落** 與 **📈 待加強**（最佳那條標黃、待加強那條標粉）。
- 段落是系統從歌詞的重複結構自動切出來的（和練唱模式的段落膠囊同一份），
  不需要事先標記。前奏、間奏、尾奏沒有導唱旋律，不列入。

什麼時候不會點名段落：

- **整首唱得很平均**時（最佳與最差差不到 5 個百分點）只顯示長條圖，
  上方寫「整首表現平均，沒有明顯拖分的段落」—— 不會為了有話講而硬挑一段來嫌。
- **唱得太短的段落**（導唱旋律不到約半秒）不參加評分，也不會被點名成最差。
- **可評分的段落不到兩段**（這首沒歌詞、或只唱一段就切歌）整塊收起來，
  總分與等級照常顯示。

搭配練唱模式很好用：把副歌用 A-B 循環唱三輪，長條圖上的副歌命中率是三輪累計的比例，
可以直接看出練起來了沒有。最佳／待加強的結論也會寫進成績歷史，
所以「這首歌我老是同一段唱壞」看紀錄就知道。

### 導唱獨立度

段落長條圖下方會多一行 **🎚️ 導唱獨立度 XX%**：這首歌有多少比例的時間，
導唱是自動淡出的（也就是你不需要它帶）。

- 這個數字比總分更能看出進步：分數會被歌難不難影響，
  但「上週副歌整段靠導唱，這週導唱退場了七成」是很直接的回饋。
- 導唱本來就沒開（純伴奏）、或這輪唱不到 20 秒不足以判斷時，**這一行不會出現** ——
  寧可不顯示，也不給一個沒有意義的數字。

## 9. 常見問題

**Q：喇叭一直嘯叫（回授）怎麼辦？**
把「🎙️ 麥克風」拉到 0 或按調音台的「乾聲」，並切回 🎧 單人模式。筆電內建麥克風 + 筆電喇叭的組合請一律使用單人模式。

**Q：字幕跟人聲對不上？**
用調音台的「🎬 字幕同步」滑桿即時修正；藍牙喇叭通常需要 +100~+300ms。

**Q：處理一首新歌要多久？**
有 NVIDIA GPU 大約 1~3 分鐘（視歌曲長度）；純 CPU 會明顯更久。處理過的歌會快取，之後秒播。

**Q：想把副歌反覆練熟怎麼做？**
開調音台的 **🔁 練唱模式**，按「副歌重唱」讓系統自動圈出副歌；
想練別段就播到定點按 **A**、**B** 自己圈，或直接點下方的段落膠囊。練完記得按「停止循環」。

**Q：快取佔太多空間？**
在 **⚙️ 系統設定 → 快取** 設一個上限並開啟自動清理，超過就會從最舊的歌開始刪
（演唱中與佇列裡的不刪）。想手動挑著刪，用「🗂️ 快取管理」分頁。
歌曲快取實體位置在 `cache/songs/`。

**Q：導唱人聲自己變小聲了，是壞了嗎？**
不是，那是 **導唱自動淡出**：你唱穩的時候導唱會讓路，唱不下去它會自己回來。
舞台右下角亮著 🎚️ 徽章就是這個狀態。不想要的話在
**⚙️ 系統設定 → 導唱自動淡出** 關掉，或把深度調成 0%。

**Q：每首歌音量差很多，一直要調音量？**
在 **⚙️ 系統設定 → 自動音量平衡** 確認已啟用（預設就是開的），
所有歌會自動補到同一個目標響度（預設 -14 LUFS）。
啟用前就快取好的舊歌，第一次播放時會現場量一次，之後就記住了。

## 10. 開發者：跑測試

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -v          # 後端單元 + API 測試（219 條）
ruff check .                        # Python lint（設定在 ruff.toml）
for f in frontend/js/*.js frontend/tests/*.js; do node --check "$f"; done   # 前端語法檢查
node --test "frontend/tests/*.test.js"   # 前端純邏輯單元測試（43 條，免 npm install）
```

前端測試用 Node 內建的測試執行器，不需要 `npm install`，
但路徑要傳 glob 字串（傳目錄會被 `node --test` 當成模組去 require）。

CI（GitHub Actions）會在每個 PR 自動跑以上檢查。
