# KaraTube 使用說明書

本文件說明 KaraTube 的啟動與所有功能的操作方式。

> 要把機器架起來給人唱（Docker、GPU、開機自啟、反向代理、備份、升級）
> 請看 [安裝與部署說明](DEPLOYMENT.md)；本文只講「架好之後怎麼用」。

---

## 1. 安裝與啟動

### 環境需求

| 項目 | 需求 |
|---|---|
| Python | 3.10 以上 |
| FFmpeg | 系統需能直接呼叫 `ffmpeg` |
| GPU | NVIDIA GPU（建議，可大幅加速 AI 分離與語音識別；無 GPU 亦可運作，速度較慢） |
| 瀏覽器 | Chrome / Edge（需支援 Web Audio API） |

### 安裝

**Docker（建議常駐使用）**

```bash
docker compose up -d
```

**直接安裝**

```bash
pip install -r requirements.txt
python run.py
```

> 開發者只想跑測試的話，安裝 `requirements-dev.txt` 即可（不含 torch / demucs 等大型依賴）。
> 完整的部署選項見 [安裝與部署說明](DEPLOYMENT.md)。

### 啟動

啟動後（直接安裝時會自動開瀏覽器）：

- **點歌控制台**：`http://localhost:8080`
- **舞台大螢幕**：`http://localhost:8080/player.html`

建議雙螢幕配置：筆電螢幕開點歌台，外接電視/投影機全螢幕開舞台頁。

> 🎙️ 舞台端要用麥克風評分的話，請跑在 `http://localhost` 或 HTTPS 之下 ——
> 瀏覽器只在安全來源給麥克風權限。

### 我在跑哪一版？

點歌台 **⚙️ 系統設定** 頁尾會顯示版本號，或直接問伺服器：

```bash
curl -s http://localhost:8080/api/version
```

回報問題時請一併附上。變更內容見 [更新日誌](../CHANGELOG.md)。

## 2. 點歌

### 搜尋點歌

1. 在點歌台上方搜尋框輸入 **歌名、歌手**，或直接貼上 **YouTube / YouTube Music 網址**。
2. 每張歌卡有兩個按鈕：
   - **🎤 點歌**：加到佇列最後。
   - **⚡ 插播**：插到佇列最前面，下一首就唱。
3. 第一次點的歌會自動走後端流水線：下載 MV → AI 人聲伴奏分離 → 歌詞對齊 → 音高抽取，佇列中會顯示處理進度。點過的歌會快取，第二次秒播。

### 曲庫分頁

搜尋框下方有十三個分頁：

- **📚 快取歌曲**：本機已處理完成的歌，點了免等待秒播。
- **🎼 分類瀏覽**：依語言別與歌手分類點歌（見下節）。
- **🔤 注音查歌**：注音首字 / 歌名字數，只查已備好的曲庫（見下節）。
- **🔢 歌號點歌**：記得號碼就打六位數，最快的一條（見下節）。
- **🎤 歌星查歌**：按歌星名字的注音首字翻開他的歌單（見下節）。
- **🆕 新歌推薦**：最近加入曲庫的新歌，加上依你的點唱紀錄產生的推薦歌單（見下節）。
- **⭐ 我的最愛**：收藏的常唱歌曲（見下節）。
- **🏆 點唱排行**：按實際上台演唱次數排序的熱門排行，顯示次數與最近演唱日期。
- **🕘 已唱歷史**：最近實際演唱過的歌（最新在前），標示演唱時間，一鍵再點。分頁上方會顯示「今天唱了幾首」。
- **📊 我的成績**：同一首唱滿三次之後，這裡告訴你「你一向強在哪一段、弱在哪一段」（見下節）。
- **🎙️ 錄唱回放**：把剛剛唱的那一次聽回來、下載、標記保留（預設關閉，見下節）；
  最上面那一條可以把**一整場**包成一個 zip 帶走。
- **🗂️ 快取管理**：每首快取歌曲的磁碟用量與完整性，可刪除或重新處理（見下節）。
- **🌙 排程預處理**：把整張播放清單丟給機器在半夜先處理好，隔天全部秒播（見下節）。

### 分類瀏覽（語言別 / 歌手）

「🎼 分類瀏覽」是商用點歌機的「分類點歌」：先縮小範圍，再從清單裡挑歌。

- **🌏 語言**：國語 / 台語 / 粵語 / 日語 / 韓語 / 英語 / 其他。
  只列出曲庫裡真的有歌的語言，每個標籤後面是首數。
- **🎤 歌手**：曲庫裡的歌手，歌多的排前面。歌手多的時候這一列可以往下捲。
- **↕️ 排序**：最新加入 / 最常點唱 / 歌名 / 歌手。
- 語言與歌手可以疊加（例如「台語」＋「江蕙」），按 **全部語言 / 全部歌手** 取消該項篩選。
- 歌卡左下角會標語言別，方便一眼分辨。

語言與歌手是伺服器自動判定的：語言看歌名、頻道名與歌詞（粵語、台語靠方言用字，
要出現兩種以上才算），歌手則從 YouTube 頻道名還原
（`周杰倫 - Topic` → `周杰倫`；頻道是唱片公司時改抓「歌手 - 歌名」的前半段）。
判定結果存在該首歌的 `metadata.json`，只算一次。

> 判錯了怎麼辦？分類只影響歌出現在哪個分頁，不影響演唱。
> 想改判可以到「🗂️ 快取管理」對該首歌按 **🔁 重新處理**（重跑後會重新判定），
> 或直接編輯 `cache/songs/<影片ID>/metadata.json` 裡的 `language` / `artist_name`。

### 注音查歌（🔤 只在已備好的曲庫裡查）

「🔤 注音查歌」是商用點歌機鍵盤上的那三條路：**注音首字**、**歌名字數**、
以及直接打歌名或歌手。

**跟上面那個搜尋框差在哪？** 搜尋框查的是 YouTube（線上點歌，點下去要等 AI
處理完才唱得到）；這一頁只查**已經備好的曲庫**，列出來的每一首按下去都是
⚡ 快取秒播。曲庫大了之後，「這首我們是不是已經有了」比「去 YouTube 找一首」
常用得多。

**怎麼用**

- **注音**：按歌名**每個字的第一個注音符號**。稻香＝`ㄉ` `ㄒ`、小幸運＝`ㄒ` `ㄒ` `ㄩ`。
  不用按完整個音，也不用管聲調。
- **字數**：按「3 個字」「5 個字」就只看那個字數的歌名（英文歌不進字數分類）。
  再按一次同一顆＝取消。
- **直接打字**：同一個輸入框也可以直接打歌名或歌手（「稻香」「五月天」）。
  英文歌可以打首字母（`YOM` ← Yesterday Once More）。
- **⌫** 退一格、**清除** 把注音與字數條件一起清掉。
- 條件可以疊：`ㄐ` ＋「5 個字」。

**幾件看起來怪、其實是刻意的事**

- **鍵盤上有些鍵是灰的**：那些鍵按下去一定沒有結果（曲庫裡沒有這樣開頭的歌）。
  跟商用點歌機一樣。灰掉的鍵不會消失，位置永遠一樣，手指才記得住。
  如果**整個鍵盤都會變灰**（例如下一個字是英文），系統反而讓全部的鍵都可以按 ——
  全灰的鍵盤沒有給任何資訊，只會讓人以為壞掉了。
- **歌卡上的歌名比 YouTube 上短**：這一頁顯示的是萃出來的**歌名本體**
  （「周杰倫 Jay Chou - 稻香 Rice Fields【Official MV】4K」→「稻香」）。
  字數與注音都是照這個算的，不然一首兩個字的歌會被算成二十幾個字。
- **多音字兩種讀音都查得到**：〈重來〉按 `ㄓ` `ㄌ` 或 `ㄔ` `ㄌ` 都找得到。
- **注音也查得到歌名中間**：〈甲你攬牢牢〉按 `ㄌ` `ㄌ` 也找得到，
  只是從第一個字開始按的結果會排在前面。

> **鍵盤不見了？** 畫面會寫「這台伺服器沒有安裝注音字典（pypinyin）」——
> 到專案目錄執行 `pip install pypinyin` 再重開服務即可（它列在 `requirements.txt`
> 裡，照安裝說明裝的話本來就有）。沒有它的時候字數與打字查詢照常可用。

### 歌星查歌（🎤 按歌星的名字找歌）

「🎤 歌星查歌」跟上一頁是同一副注音鍵盤，但按的東西不一樣：
上一頁按的是**歌名**的字，這一頁按的是**歌星名字**的字。
想不起歌名、但記得自己要唱誰的時候用這一頁。

**怎麼用**

- **注音**：按歌星名字**每個字的第一個注音符號**。周杰倫＝`ㄓ` `ㄐ` `ㄌ`、
  五月天＝`ㄨ` `ㄩ` `ㄊ`。
- **英文名**：按首字母。Jay Chou＝`J` `C`、Carpenters＝`C`。
- **直接打字**：同一個輸入框也可以直接打名字（「五月」就找得到五月天）。
- **點一位歌星**：下面就換成他在曲庫裡的全部歌，每一首都是 ⚡ 快取秒播。
  再點一次同一位＝取消，回到整份歌星清單。
- **⌫** 退一格、**清除** 把注音與選定的歌星一起清掉。

**幾件看起來怪、其實是刻意的事**

- **按到只剩一位歌星時，畫面自己翻開他的歌單**。標題會寫「（只剩這一位，
  直接翻開歌單）」—— 那不是誤觸，是少讓你點一下。
- **歌星鈕上寫著「也寫作 Jay Chou」**：同一位歌星在曲庫裡常有好幾種寫法
  （看那首歌是從哪個頻道抓來的），系統會把它們併成一位，歌單是完整的那一份。
  按中文注音或按英文首字母都會落在同一位。
- **有時候同一位歌星還是會出現兩筆**（例如「周杰倫」與「Jay Chou」各自一筆）：
  當曲庫裡沒有任何一首歌把兩種寫法寫在一起時，系統**不猜**它們是同一個人 ——
  猜錯的話你的歌單裡會混進別人的歌。等哪天有一首歌的來源同時寫了中英文名，
  兩筆就會自動合起來。
- **清單最後那個「未知歌手」**：那些歌從頻道名與標題都認不出是誰唱的。
  它不會被注音查到（它不是名字），但歌都在裡面，點進去照樣唱得到。

> 想改某一首歌的歌星？到「🗂️ 快取管理」對該首歌按 **🔁 重新處理**，
> 或直接編輯 `cache/songs/<影片ID>/metadata.json` 裡的 `artist_name`。

### 歌號點歌（🔢 打六位數，最快的那一條）

每一首備好的歌都有一組**六位數歌號**（從 100001 開始），印在歌卡的歌名底下、
佇列上那一首，以及唱之前舞台上的片頭卡（「🔢 歌號 100237」）。
記住號碼的人，坐下來按六下就點完了 —— 不必想關鍵字、不必挑注音。
這也是包廂裡唯一可以**用喊的**那一條：「幫我點 100237」。

**怎麼用**

- 「🔢 歌號點歌」分頁按數字鍵，上面的格子會顯示 `1 0 0 ＿ ＿ ＿`（還差幾碼一目了然）。
- **不必打滿才有東西看**：打前幾碼，下面就列出所有以這幾碼開頭的歌。
- 打滿六碼之後，畫面會說「找到了：稻香」並出現一顆 **🎤 點這首**。
  **要再按那一下**才會點歌 —— 按錯一碼是常事，直接送出的話，你的下一個動作
  會是去佇列裡把它刪掉。
- **⌫** 退一格、**清除** 重打。

**幾件看起來怪、其實是刻意的事**

- **號碼永遠不會變成別首歌。** 這是這個功能唯一的承諾，也是它值得你去記的
  唯一理由。就算那首歌被刪掉了，那組號碼也不會被別首歌撿走。
- **打到一組已經下架的號碼時，機器會說清楚**：

  > 100237 是「稻香」，但它已經不在曲庫裡了。用上面的搜尋框重新處理一次，
  > 回來還是這組號碼。

  所以看到這句話不必重記號碼 —— 那首歌重新處理好之後，號碼原封不動。
  （砍掉重跑、刪掉又點一次，都是同一組號碼。）
- **數字鍵永遠都按得下去**，不像注音鍵盤會把查不到的鍵變灰。理由就是上面
  那一句：已經下架的號碼要打得完，你才看得到它去哪了。按下去會落在現有的歌上
  的鍵會**標亮**，那是提示，不是限制。
- **號碼只發給已經備好的歌**，所以歌號查出來的每一首都是 ⚡ 快取秒播。
  剛從 YouTube 點的新歌要等流水線跑完，才會拿到自己的號碼
  （跑完那一刻就會出現在佇列上）。
- **「已下架 N 組號碼」** 是正常的：那是號碼不回收的成本，也正是它可靠的原因。

> 想印一份紙本歌本？`GET /api/library/songbook` 會照號碼順序給出整本號碼簿
> （含已下架的號碼，因為紙印出去之後改不了，而那一頁上的號碼永遠不會變成別首歌）。

> **萬一畫面說「歌號暫停服務」**：代表 `cache/song_numbers.json` 讀不出來。
> 系統**不會**重發一套新號碼（那等於把大家記住的號碼全部改掉），
> 而是整個歌號功能先停掉，其他查歌方式照常。把那個檔案修好或還原備份即可。

### 新歌推薦（新歌榜 + 為你推薦）

「🆕 新歌推薦」分頁分成上下兩區：

- **🆕 新歌榜**：最近加入曲庫的歌，最新排最前面；14 天內加入的會標上 **NEW** 徽章。
- **💡 為你推薦**：依你的點唱紀錄推回「接下來唱什麼」，每張卡片都寫出推薦理由：
  - 「好久沒唱了，再來一次？」—— 唱過兩次以上但最近沒再點的老歌。
  - 「你唱過 XXX，這首還沒唱過」—— 最近唱過的歌手的其他歌。
  - 「剛加入曲庫，還沒開嗓過」—— 曲庫裡從沒唱過的歌。

### 我的最愛（收藏）

- 每張歌卡右上角有星星按鈕：**☆ 未收藏 / ⭐ 已收藏**，點一下切換。
- 收藏在「⭐ 我的最愛」分頁集中管理，最新收藏排最前面，一鍵再點歌。
- 收藏存在 `cache/favorites.json`，重開機不會消失。

### 多人包廂暱稱（誰點的歌）

- 點歌台（含每支掃碼連入的手機）右上角有 **👤 設定暱稱** 按鈕，輸入自己的暱稱。
- 設定後點的每一首歌，佇列上都會掛 **👤 暱稱** 標籤，舞台片頭卡也會顯示「點歌：XXX」。
- 暱稱存在各裝置自己的瀏覽器（localStorage），每個人只要設定一次；不設定也能照常點歌，只是不顯示標籤。

### 佇列管理

- 右側「點歌排隊佇列」顯示待唱清單與每首歌的處理狀態，以及是誰點的（有設定暱稱時）。
- **拖曳排序**：按住每首歌左側的 **⠿** 把手上下拖曳即可調整演唱順序，
  桌機滑鼠與手機觸控都支援，放手後所有裝置的佇列即時同步。
  （佇列只有一首歌時不顯示把手 —— 沒得排。）
- 點 **✕** 可把歌從佇列移除。
- 處理失敗的歌（紅色「● 處理失敗」）會多一顆 **🔁** 重試按鈕 ——
  網路斷線、影片暫時抓不到之類的暫時性錯誤，重跑一次通常就過了，不用重新搜尋點歌。
- 佇列裡的歌唱完會自動接下一首就緒的歌。

### 公平輪唱（🔁 一個人連點五首時，其他人不必等完那五首）

包廂裡最常吵的從來不是音準，是**順序**。一個人連點五首，其他人就得等五首；
後到的朋友想唱一首，排在最後面，等到散場都還沒輪到。

佇列標題右邊那顆按鈕就是這件事的開關：

| 按鈕顯示 | 意思 |
|---|---|
| 🔁 先到先唱 | 預設。新點的歌一律排到最後面（和以前一樣）。 |
| 🔁 輪唱中 | 新點的歌照「這是誰的第幾首」插進佇列，大家輪流唱。 |

按下去所有裝置同步 —— 排序規則是要大家都知道才不會吵的東西。

**怎麼排的**

```
佇列：  小明①  小明②  小明③          ← 小明一口氣點了三首
小美點一首（她今晚的第一首）
佇列：  小明①  小美①  小明②  小明③   ← 插在小明的第二首前面
```

「第 N 輪」的意思是「這是他今晚的第 N 首」（**包含已經唱完的**）。
所以唱完一首再點的人，不會排到還沒唱過的人前面。

**幾件先知道比較好的事**

- **已經排好的順序不會被重排**。輪唱只決定新點的那一首插進哪裡；
  已經在佇列上的歌不會因為有人點歌而跳來跳去，手動拖曳的結果也不會被吃掉。
- **⚡ 插播不受影響**，永遠是下一首。插播是現場有人按下去的決定，
  機器的規則不該推翻它。（但插播照樣算他的一輪。）
- **要設暱稱**（右上角 👤）。輪唱認的是暱稱，不是哪一支手機 ——
  包廂裡的手機是傳來傳去的。沒設暱稱的所有人會被算成**同一位**，
  所以一整間都沒設的話，行為就等於先到先唱（佇列上方會直接寫這件事）。
- **點完歌會告訴你排到哪**：「🎤 已加入：🔁 排在第 2 位（小美的第 1 輪），
  插到 3 首前面」。
- 佇列上方那一行是現在的全貌：誰已經唱了幾首、還有幾首待唱。

**重新排（換一批客人時）**

按佇列上方的 **重新排**，把「誰今晚唱過幾首」歸零。
**佇列不會變動** —— 已經排好的順序是大家看著排出來的，歸零的只是統計，
影響的是接下來新點的歌。

沒人唱歌超過 6 小時（⚙️ 系統設定的「相隔幾小時算換一場」，與整晚打包共用
同一個值）也會自動歸零 —— 昨晚唱了八首的人，今晚第一首不該被排到所有人後面。

### 每人待唱上限（🎫 佇列不要被一個人塞滿）

輪唱管的是**順序**，這一條管的是**量**。輪唱會把一個人連點的五首攤開來排，
但那五首還是在佇列裡；人一多，散場前佇列還是清不完（而且排最後面那幾首的
點歌者早就走了，歌照唱，沒人上台）。

佇列標題右邊的 **− 🎫 ＋** 就是這件事：

| 顯示 | 意思 |
|---|---|
| 🎫 不限首數 | 預設。想排幾首都可以（和以前一樣）。 |
| 🎫 每人 3 首 | 一個人同時最多只能有 3 首在等。 |

`−`／`＋` 一次調一首，按中間的標籤在「不限」與剛剛那個數字之間切換。
調整後所有裝置同步 —— 這條規則要大家都知道才不會變成吵架的來源。

**排滿了怎麼辦？等一首唱完就好**

上限算的是「**同時**排幾首」，不是「今晚總共唱幾首」。所以排滿只是暫時的：
自己其中一首上台，那一格就空出來，馬上又能點。沒有人會被鎖在今晚之外，
也不需要誰去後台按重設。

被擋下來時畫面會直接講清楚：

> ⚠️ 小明 已經排了 2 首待唱（上限 2 首）。你的下一首排在第 1 位，唱完就空出一格。

**幾件先知道比較好的事**

- **一定要設暱稱**（右上角 👤）。沒設暱稱的所有人**共用同一份額度** ——
  所以在開了額度的包廂裡，設暱稱是有好處的：你才拿得到屬於自己的那幾首。
  （沒設的人被擋下來時，畫面會直接告訴他這件事。）
- **⚡ 插播不受上限限制**，但它**照樣佔掉一格**。插播是現場有人按下去的決定，
  機器的規則不該推翻它；但如果它不算額度，那就變成繞過上限的按鈕了。
- **正在唱的那一首不佔額度**，只有還在等的才算。
- **調低上限不會刪掉任何歌**。已經排好的歌一首都不會動，只是在降回上限以下
  之前點不了新的。
- 額度開著時，佇列上方會多一行寫出現在誰排了幾首：
  「每人最多排 2 首待唱　小明 2/2 滿　小美 1/2」。

### 包廂計時（⏱️ 歡唱時間還剩多久）

包廂買了三小時、或是十點以前一定要收工的場合用得到。預設**關著**
（家裡唱歌沒有人在算時間），到「⚙️ 系統設定 → ⏱️ 包廂計時」打開。

打開之後，點歌台右上角會多出一組：

| 按鈕 | 意思 |
|---|---|
| ⏱️ 開始計時 | 還沒開錶。按下去就照設定的長度開一場（預設 3 小時）|
| ⏳ 1:23:45 | 倒數中。按下去可以**結束計時**（會問一次）|
| ⏸️ 暫停 1:23 | 停錶中。時間不會被算掉 |
| ＋30 分 | **續時**：加時間（不是重開一場）|
| ⏸️ / ▶️ | 停錶／繼續。中場休息、餐點來了用，**播放不受影響** |

**時間到之後會怎樣？（這是最重要的一件事）**

時間到**不會**把正在唱的那一首停掉。它會唱完，唱完之後機器才停下來，
不再播下一首。所以最壞的情況也只是超時一首歌的長度，而且你在剩十分鐘的時候
就已經知道會這樣了。

**佇列一首都不會被刪。** 停下來的是播放，不是資料 —— 按下「＋30 分」續時，
機器會自己接著播下一首，排好的歌原封不動。

**提醒**

剩 10 分鐘、剩 3 分鐘、時間到各提醒一次（分鐘數可以改，設 0 就是不提醒）。
每一次都會把「時間到會怎樣」與「怎麼續時」講出來：

> ⏳ 歡唱時間剩 10 分鐘。時間到會讓正在唱的那一首唱完，然後就不再播下一首
> （佇列不會被清掉）。需要的話在點歌台按「＋30 分」續時。

舞台大螢幕只在**最後十分鐘**才會在上方亮出倒數（前面那兩小時不顯示，
免得跟歌詞搶畫面），最後一首唱完後會亮出散場畫面。

**幾件先知道比較好的事**

- **第一首歌會自動開錶**（可在設定頁關掉）。不自動開的話，最常見的情況是
  三小時後才有人想起來沒按開始，那時候已經補不回來了。
  但按過「結束計時」之後就不會再自動開。
- **時間到之後點不了新歌**（連 ⚡ 插播也不行），畫面會告訴你續時就可以接著唱。
  已經排好的歌都還在。
- **剩不到 5 分鐘時點歌**，會多提醒一句「這首可能唱不完」。
- **重開機接得回來**。伺服器重開（或斷電再開）不會讓時間歸零，也不會憑空
  多出時間；但機器關超過 12 小時再開，昨天那一場就不接續了。
- 只想要提醒、不想被停歌的話，把設定頁的「時間到怎麼辦」改成
  **只提醒，不停歌**。

### 舞台訊息（📺 把一句話打到包廂螢幕上）

餐點送到門口、有人要唱生日歌、該提醒麥克風傳給下一位 —— 商用點歌機讓櫃檯
把字打到包廂螢幕上，這裡是同一件事，而且包廂裡任何一支手機都送得出去。

**怎麼送**

1. 點歌台（或手機）最上排按 **📺 舞台訊息**。
2. 打一句話（最多 40 字），或直接按下面的常用句（餐點在門口的那十秒鐘，
   沒有人想打字）。
3. 按「送到舞台」或直接按 Enter。

| 選項 | 意思 |
|---|---|
| ⚡ 緊急 | 排到最前面，而且停留久一點。**不會**因此蓋住歌詞 |
| 📌 釘住 | 一直留在輪播裡直到撤掉（最長 4 小時），生日祝福用 |

**它會出現在哪裡**

- **正在播歌**：畫面**最上緣**一條。它會把歌名、倒數與分數那一排往下推 ——
  不是疊在上面，所以不可能蓋到任何一個字，歌詞與音準線完全不受影響。
- **沒有人在唱歌**：畫面正中央的大字卡，看一眼就知道。

緊急訊息在播歌時**一樣**只走最上緣那一條。沒有哪一則訊息重要到值得擋住
正在唱的那個人；真的那麼急的事，走到包廂門口敲門比較快。

**它不會捲動**。會動的字會一直把餘光拉過去，而唱歌的人正需要那個餘光看歌詞。

**幾件先知道比較好的事**

- **每一則會自己消失**（預設 10 分鐘，可在設定頁改）。「您的餐點到了」
  在四十分鐘後才出現，比沒有訊息更糟。要久一點的用 📌 釘住。
- **同時最多 8 則**，多則會輪流顯示（一次只講一件事）。滿了會告訴你
  「等一則播完、或先撤掉一則」。
- 面板下方列出**現在螢幕上的訊息**（誰送的、還剩多久），每一則都可以單獨
  「撤掉」，也可以「全部撤掉」。最上排那顆鍵右上角的數字就是現在有幾則。
- **伺服器重開之後訊息是空的**（刻意的）：重開之後那件事多半早就處理完了，
  而一則沒有人記得的舊訊息自己跳出來，看起來就像機器壞了。
- 不想要這個功能的話，到「⚙️ 系統設定 → 📺 舞台訊息」關掉。

### 服務鈴（🔔 包廂叫櫃檯）

上一節是**櫃檯 → 包廂**，這一節是**包廂 → 櫃檯**：想加冰塊、餐點還沒來、
3 號麥克風沒聲音、想結帳。商用點歌機上那顆「服務」鍵就在這裡，
而且包廂裡任何一支手機都按得到 —— 不必有人推開門走出去找服務生
（而那個人通常正是唯一知道要加什麼的那位）。

**怎麼按**

1. 點歌台（或手機）最上排按 **🔔 服務鈴**。
2. 選要什麼（**可以複選**）：🛎️ 服務人員、🍽️ 送餐／加點、🧊 加冰塊／飲料、
   🧹 清潔／收桌、🎤 麥克風／音響、🧾 結帳、✏️ 其他。
3. 需要的話打一句備註（最多 40 字，例如「少冰」「兩杯」「3 號麥克風」）。
4. 按 **🔔 叫櫃檯**。

**按完之後你會看到什麼**

那張單會**一直留在面板最上方**，寫著現在是哪一種狀態、已經等多久：

| 狀態 | 意思 |
|---|---|
| 🔔 已送出，等櫃檯回應 | 單子開著，還沒有人應聲 |
| 👀 櫃檯收到了，正在處理 | 櫃檯按過「收到」了 —— 有人在弄了 |
| ✅ 已完成 | 櫃檯處理完（可能還附一句回覆） |
| ↩️ 包廂自己取消 | 你們自己按了「取消」 |
| ⌛ 太久沒有人處理 | 開超過 45 分鐘（可調），自動關閉 |

**「已送出」跟「櫃檯收到了」是兩件不同的事**，所以分成兩種狀態、而且那句話
不會自己消失。跳一下就不見的「已送出」等於沒有回應：三十秒後你手上什麼都沒有，
唯一能做的就是再按一次。

**已經在等了，再按一次會怎樣**

不會變成第二張單，會**併進同一張**：

- 多選的品項加進去（先叫送餐、後來想到要冰塊 → 櫃檯一趟送完）。
- 備註接在後面，不是覆蓋掉前一句。
- 櫃檯那一列會顯示「**按了 3 次**」—— 催單這件事會被看見。
- **等待時間不會重算**。從你**第一次**按下去算起，所以等最久的那一桌
  不會因為按最多次反而被排到最後面。

**櫃檯那一端**

同一個面板上有三顆鍵（櫃檯與點歌台是同一台機器時，它們就在一起）：

| 鍵 | 誰按 | 做什麼 |
|---|---|---|
| 👀 櫃檯收到 | 櫃檯 | 讓包廂看到「我們收到了」。不改變任何事，卻是客人還會不會再按一次的分水嶺 |
| ✅ 完成 | 櫃檯 | 這件事處理完了，可以順便回一句（「餐點五分鐘後到」） |
| ↩️ 取消 | 包廂 | 不用了，我們自己去拿 |

等太久的單會變色（5 分鐘轉黃、10 分鐘轉紅）。已經按過「收到」的單**降一級** ——
讓人再按一次的從來不是等待本身，是沒有回音。

**幾件先知道比較好的事**

- **這幾個字一個都不會出現在舞台螢幕上**。台上那個人沒有點那份冰塊，
  單子的狀態對他沒有用；那面螢幕是全場唯一大家都在看的，不該拿來講
  一件跟一個人有關的事。（櫃檯想在螢幕上講話，用上一節的 📺 舞台訊息。）
- **有單在等的時候，最上排那顆 🔔 會亮**（不必打開面板就看得到），
  而且有新單時點歌台會提示一聲（櫃檯與點歌台是同一台時可以在設定頁關掉）。
- **伺服器重開之後，還開著的那張單還在**（跟舞台訊息刻意相反）：
  它對應的是現實世界裡一件還沒做完的事，重開機不會讓那杯冰塊自己送到。
- **「取消」跟「完成」在紀錄上分得開**，所以「今晚有幾單沒服務到」問得出來。
- 面板下方是**今晚的服務紀錄**。「清除紀錄」只清紀錄，**不會**把還在等的
  那張單一起清掉。
- 不想要這個功能的話，到「⚙️ 系統設定 → 🔔 服務鈴」關掉。

### 自動接歌（🎧 沒有人點歌時，機器自己接一首）

一首唱完、佇列空了，包廂就安靜下來 —— 那三十秒是氣氛最容易斷掉的地方。
打開這個功能，機器會自己從**已經備好的曲庫**接一首上來墊檔。
預設**關著**，到「⚙️ 系統設定 → 🎧 自動接歌」打開。

| 設定 | 預設 | 意思 |
|---|---|---|
| 啟用自動接歌 | 關 | 打開之後機器才會自己出聲 |
| 照什麼挑 | 混著挑 | 混著挑／只挑我的最愛／只挑常點的歌／只挑還沒唱過的 |
| 空多久才接 | 20 秒 | 佇列空了幾秒之後才接。0 = 一空就接 |
| 連著接幾首就停 | 3 首 | 接滿就安靜下來，有人點一首就重新計數 |

**它接的歌從哪裡來？**

只從曲庫（已經處理好、可以秒播的那些歌）挑，**不會去 YouTube 抓新歌**——
那要幾分鐘，而且會把運算資源吃光，剛好卡在真的有人點歌的時候。
剛接過的十幾首不會再重複；已經排在佇列裡的歌一首都不會被它挑走。

**我點歌的話，它會怎麼樣？**

- 機器接的那一首**開播 45 秒內**（大概還在前奏）：立刻讓位，換上你點的歌。
- **超過 45 秒**：讓它唱完，你點的那一首排在後面 —— 有人跟著唱到一半被切掉，
  比多等一下難堪。等不了的話按切歌（⏭️）就好。

佇列上方那一行會把現在的狀態講出來，舞台的片頭卡也會標「🎧 自動接歌・
有人點歌就讓開」，所以不會有人以為是誰偷點的歌。

**機器接的歌不算任何人的一首**

不會進熱門點唱排行（不然排行會變成機器自己的回音）、不會進已唱歷史、
不佔輪序與點歌額度，也**不會把包廂計時的錶打開**。

**🎲 來一首（不必開自動接歌也能用）**

佇列上方那顆 🎲 是另一件事：想唱歌但想不到要唱什麼的時候按它，
從曲庫隨機點一首。它挑法跟自動接歌一樣（設「只挑我的最愛」時 🎲 也照辦），
但**算你點的** —— 會計入排行與歷史，也照樣受點歌額度與歡唱時間限制。
通知會講出「為什麼是這首」（⭐ 我的最愛 / 🌱 還沒唱過 / 🔥 常點的歌）。

曲庫還是空的時候按 🎲，機器會告訴你先搜尋點一首，處理好就會留在曲庫裡。

### 快取管理

「🗂️ 快取管理」分頁是發布機台的日常維運入口：

- 分頁上方顯示 **快取幾首歌、共佔多少空間、磁碟還剩多少**。
- 每首歌一列，顯示磁碟用量與完整性徽章：
  - **完整**：四個必要檔案（伴奏、人聲、歌詞、metadata）都在，可直接點歌。
  - **不完整**：處理中斷或失敗的殘留（缺哪些檔案滑鼠移上去看得到），照樣佔磁碟。
- **🎤 點歌**：完整的歌直接排入佇列秒播。
- **🔁 重新處理**：砍掉現有快取、重跑整條流水線（下載 → AI 分離 → 字幕對齊 → 音高抽取）。
  字幕全歪、伴奏有雜音、檔案缺漏時用這顆。需要幾分鐘，完成後自動就緒。
- **🗑️ 刪除**：刪掉快取釋放磁碟空間，下次再點會重新處理。
- **演唱中或還在佇列裡的歌不能刪也不能重新處理**（會直接讓舞台斷片），先切歌或從佇列移除再操作。

### 排程預處理（半夜先把整批歌處理好）

第一次點一首新歌要等下載＋AI 分離＋字幕對齊好幾分鐘。「🌙 排程預處理」分頁
讓你把這段等待挪到**沒人唱歌的時候**：晚上把清單貼進去，隔天全部秒播。

**怎麼用**

1. 開「🌙 排程預處理」分頁，把來源貼進大框框，**一行一個**（逗號分隔也可以）：
   - YouTube **播放清單**網址（`.../playlist?list=...`）→ 整張清單展開
   - 單曲網址或 11 碼影片 ID → 就那一首
   - 歌名關鍵字（例：`周杰倫 稻香`）→ 搜尋結果的第一首
2. 可以填這批的名稱（例：「週末歌單」），方便隔天回來對照。
3. 按 **🌙 加入排程**。已經在曲庫裡的歌會直接標成「略過」——
   貼 30 首常常只有 3 首真的要跑。
4. 想現在就跑不等時段，勾 **立即開始**（或按分頁上的 **⚡ 立即開始**）。

**它什麼時候會動**

- 預設只在 **02:00–06:00** 開工（可在 ⚙️ 系統設定改，跨午夜如 23→6 也可以，
  起訖設成同一小時 = 全天候）。
- **有人在唱歌時一定讓開**。每處理完一首就重新確認一次，
  所以客人進包廂點歌後，最多再等一首歌的時間機器就會把資源讓出來。
- 狀態列永遠寫著「現在為什麼還沒開始」（等時段／有人在唱／功能被關掉／沒歌要處理），
  不用猜。

**跑不完或跑壞了**

- 一首失敗（影片被下架、網路斷線）只影響那一首，其餘照跑；
  按 **🔁 重試失敗** 只重跑壞掉的那幾首。
- **✖ 取消** 取消還沒跑的部分（正在處理的那一首會讓它跑完，中途砍掉只會留半成品）。
- **🗑️** 刪掉紀錄，已經處理好的歌留在曲庫裡不受影響；**🧹 清紀錄** 一次清掉跑完的批次。
- 排程存在 `cache/batch_jobs.json`，**重開機會續跑**；中斷在半路的那一首會重跑一次。

### 已唱歷史

- 「🕘 已唱歷史」分頁記錄每一次實際上台的演唱（同一首唱三次就有三筆），排進佇列又被刪掉的不算。
- 卡片上顯示演唱時間（今天的顯示「今天 21:34」），點 **🎤 點歌** 即可再唱一次。
- 歷史存在 `cache/song_history.json`，保留最近 500 筆，重開機不會消失。

### 我的成績（你一向強在哪一段）

「📊 我的成績」分頁不是排行榜，是**練歌用的**：同一首歌唱滿三次之後，
這裡會告訴你「這首歌的副歌 2 你**一向**掉 13 個百分點」。

- 每一張卡是「一首歌 × 一位演唱者」：主場段落（🏠）、待加強段落（📈）、
  一張中線是「你自己的平均」的長條圖（往右是強項、往左是弱點），
  以及這段期間是在進步還是退步。
- 卡片右上角的 **🎤 再唱一次** 直接把這首排進佇列。
- **唱不到三次的歌不會出現在這裡**。唱一次就說「你一向如何」是唬人的 ——
  那一次可能只是沒接上氣。
- 為什麼是「跟自己的平均比」而不是直接看命中率：感冒那天每一段都會掉，
  直接看命中率的話每一段都變成弱點。減掉當天自己的平均之後，
  比的是**這一場的形狀**，狀況好壞不影響結論。
- 每個人的成績分開算（對唱模式兩位各自累積）。段落弱點是**這個人**的弱點，
  三個人的副歌混在一起平均，算出來的只是這首歌的副歌難不難唱。
- 一段唱得時好時壞（方向不一致）時不會被點名，長條圖上畫成淡色 ——
  那代表「還沒有結論」，不是「剛好等於平均」。

### 錄唱回放（把剛剛唱的那一次聽回來）

「🎙️ 錄唱回放」分頁是**唱完之後**的那一半：分數說的是唱得好不好，
錄音說的是唱起來是什麼樣子。

**要先打開**：⚙️ 系統設定 → 🎙️ 錄唱回放 → 把「錄唱回放」切成開啟。
預設是關的 —— 錄音錄到的是包廂裡所有人的聲音，這件事該由人決定，不該由預設值決定。
打開之後，**下一首**開始唱就會錄。

錄著的時候舞台畫面左上角會有一個紅點「● 錄音中」。它不會消失，也不能關掉：
正在被錄音是一件要讓所有人一眼看到的事。

每一列是一次演唱（同一首唱三次就有三列），可以：

| 按鈕 | 做什麼 |
|------|--------|
| 播放器 | 就地聽（第一次按播放時會多等一下 —— 見下方說明） |
| ⬇️ 下載 | 存成檔案帶走（Chrome / Firefox 是 `.webm`，Safari 是 `.m4a`） |
| 🎧 MP3 | 轉成 MP3 再下載 —— 車機、舊手機、傳給別人用（見下節） |
| 🔗 分享 | 產生有時效的連結與 QR，讓唱的人用自己的手機帶走（見下節） |
| 📍 保留 | 標記保留：配額滿了自動清理時**不會**刪到它 |
| 🗑️ 刪除 | 刪掉這一次 |
| 🎤 再唱一次 | 把這首歌直接排進佇列 |
| 🗑️ 清空 | 清掉全部**沒有**標記保留的錄音 |

**哪些唱過的不會出現在這裡**：

- 唱不到 10 秒的（可在設定頁調）。前奏就被切歌、麥克風擺在桌上沒人唱的那種
  一樣佔空間，而且會把真正想找的那一次擠掉。算的是「**有人在唱**」的時間，
  不是歌放了多久。
- 按了 **🔄 重唱** 的那一段。重唱時評分也歸零了，留著音檔會配上一份對不起來的成績。
- 功能沒開的時候唱的（分頁上會直接告訴你「目前是關閉的」）。

**被切歌的會留下來** —— 唱了兩分鐘才被切掉，那兩分鐘一樣是一次演唱。
**歌暫停時錄音也跟著暫停**（那時候包廂在講話），錄音長度也不含暫停的那段。

**配額**：預設最多 50 首 / 512 MB（設定頁可調）。錄音跟歌曲快取共用同一顆磁碟，
所以一定有上限 —— 沒有上限的話，總有一天會變成「歌曲下載不下來」，
而那時候沒有人會想到是錄音吃光的。超過時從**最舊、沒有標記保留**的那一筆開始刪；
用到九成時分頁上會先提醒。唱得最好的那一次通常也是最舊的那一次，記得按 📌。

### 分享錄音（讓唱的人自己帶走那一次）

唱完那一句「傳給我」在這裡結案。在錄音那一列按 **🔗 分享**，會跳出一個視窗：

- 一張 **QR Code** —— 唱的人拿自己的手機掃，直接在手機上播放、下載。
- 一行**連結**（可以按「📋 複製連結」貼到群組裡）。
- 一行說明：**還有幾小時就過期**。

**連結有時效**，預設 **24 小時**（設定頁可調，最長 30 天）。
刻意沒有「永不過期」這個選項：錄到的是包廂裡所有人的聲音，
一個永遠有效、誰拿到都打得開的公開連結，事後想收也收不回來。

| 情況 | 會怎麼樣 |
|------|---------|
| 同一筆再按一次 🔗 分享 | **沿用同一個連結**（已經掃過的 QR 繼續有效） |
| 按 🚫 撤銷 | 立刻打不開。再按分享會得到一個新的連結 |
| 時間到 | 自動失效，打開的人會看到「已經過期，請原點歌的人重新分享」 |
| 錄音被刪除或被配額擠掉 | 連結跟著失效，打開的人會看到「這一次的錄音已經不在了」 |
| 設定了「下載幾次就失效」 | 只算**真的按下載**的次數；聽幾次、拖幾次進度條都不算 |

> **⚠️ 連結預設只在同一個網路裡打得開。**
> 分享連結指的是包廂這台機器的網址（例如 `http://192.168.1.50:8080/share/...`），
> 客人離開這個 Wi-Fi 之後就連不上了 —— 這時候畫面上會直接說「連不上包廂的那台機器」。
> **想讓人帶回家聽**：請先在部署時設好 `KARATUBE_PUBLIC_HOST`
> （見 [DEPLOYMENT.md](DEPLOYMENT.md)），讓連結指向一個對外打得到的位址。
> 在那之前，最保險的做法是請當事人**在包廂裡就先按下載**。

不想開放這個功能的話：⚙️ 系統設定 → 🔗 錄音分享 → 把「允許分享錄音」關掉，
分享鈕按下去會直接說明這台機器沒有開放分享。

### 轉成 MP3（車機、舊手機、傳給別人）

帶走那一次還不夠，要**在帶去的地方打得開**。錄音是瀏覽器錄的
（Chrome / Firefox 是 webm、Safari 是 mp4），這兩種在電腦與新手機上都沒問題，
但下面這些地方多半只認 **MP3**：

- 車上的 USB 播放清單（最常見的用途）；
- 長輩手上的舊手機、平板、MP3 隨身聽；
- 傳進群組之後對方直接點開（有些版本不認 webm）。

**怎麼用**：錄音那一列按 **🎧 MP3**，或是在分享頁上按 **🎧 下載 MP3**。

| 情況 | 會怎麼樣 |
|------|---------|
| 第一次按 | 按鈕變成「⏳ 轉檔中…」，等幾秒鐘（機器在真的轉一次） |
| 第二次按同一筆 | 秒回（轉好的留著當快取） |
| 一桌人同時按 | 一個一個來 —— 唱歌優先，不讓轉檔把機器卡住 |
| 看不到這顆按鈕 | 設定頁關掉了，或這台機器上沒有 ffmpeg（清單上會直接寫哪一種） |

**轉好的 MP3 不會佔到錄音的額度**，也**永遠不會擠掉任何一次演唱**：
它有自己的上限（錄音配額的 1/4，額外佔用），滿了從最久沒用到的那一份開始刪 ——
演唱刪掉就沒有，MP3 再轉一次就有。想手動清掉就按清單上方的
**🧹 清除 MP3 快取**（錄音一個都不會動）。

檔案裡會寫上歌名與演唱者（車機螢幕顯示的就是這個），
檔名是 `20260913-2130 歌名 - 演唱者.mp3`。

**為什麼進度條要等一下才拖得動**：瀏覽器錄出來的檔案格式（webm）裡沒有寫長度 ——
錄的時候還不知道會錄多久。第一次按播放時，系統會先讓瀏覽器把檔案掃過一遍算出長度，
之後進度條就正常了。清單上顯示的長度（例如 `3:24`）不受這件事影響，
那是錄的當下量好存起來的。

### 整晚打包（一個 zip 帶走一整場）

收場的時候常聽到的是另一句話：「今天晚上的通通給我一份」。
一首一首按下載是二十幾次另存新檔，而且存出來散在資料夾裡分不出誰是誰。

「🎙️ 錄唱回放」分頁**最上面**那一條就是打包列：

| 看到的 | 意思 |
|------|------|
| `今晚 21:05 – 隔天 02:30` | 這一場的起訖。**跨午夜是同一場**，所以寫得出「隔天」 |
| `23 首・3 人・186.4 MB` | 這一場有幾首、幾個人唱過、整包大約多大 |
| 下拉選單 | 預設「全部」，也可以只要某一位唱的那幾首 |
| ⬇️ 打包下載 | 按下去開始下載（會顯示最近三場） |

**解開之後長這樣**：

```
KaraTube 20260913 23首.zip
├── 01 21-05 月亮代表我的心 - 阿明.webm
├── 02 21-11 海闊天空 - 小美.webm
├── ...
└── 曲目.txt          ← 誰在幾點唱了什麼、幾分、多長
```

檔名前面的**序號與時間**是刻意的：車機、隨身碟播放器與電腦的檔案總管都是
照檔名排序的，有序號才留得住「今晚唱的順序」。

**幾件先知道比較好的事**：

- **進度條不會顯示百分比**，只會顯示已經下載了多少 —— 因為機器是**邊打包邊送**的
  （不先在自己的磁碟上生一份，那會多佔一整場的空間）。它沒有卡住。
- **一次只能打一包**。有人正在打的時候按下去會被擋下來並說明，等它下載完再按。
- **包裡是原始格式（webm / mp4）**，不是 MP3：一整晚三十首要轉三十次，
  等於拿正在放歌的 CPU 去換檔案。要 MP3 的話按那一首自己的 🎧 MP3。
- **這條路只有點歌台有**。分享連結（掃 QR 的那一種）拿不到整晚打包 ——
  一個 zip 是整場所有人的聲音。
- 打包的當下如果剛好有某一首被配額擠掉了，那一首會被跳過，
  而且 `曲目.txt` 裡會寫出來是哪一首。

**「一場」怎麼算**：相隔超過 6 小時才算換一場（設定頁可調）。
所以「九點唱到凌晨兩點半」是一場，而「下午一輪、晚上一輪」是兩場 ——
照日曆日期切的話這兩件事都會算錯。

## 4. 調音台（🎛️ 按鈕）

- **升降 Key**：♭ 降 / ♯ 升，範圍 -6 ~ +6 半音，「原」一鍵歸零。
- **快速調性（男調/女調）**：商用點歌機的一鍵變調 ——
  **♂ 男調** 一鍵降 4 個 Key（女歌男唱）、**♀ 女調** 一鍵升 4 個 Key（男歌女唱）、**原調** 回到原 Key。
  按了之後仍可用 ♭/♯ 微調；目前 Key 值所有裝置即時同步。
- **演唱模式**：
  - 🎧 **單人**：人聲不進喇叭，不可能回授，適合筆電內建麥克風。評分照常。
  - 🔊 **多人**：人聲外放，**務必使用外接喇叭**。
- **效果風格（一鍵套用）**：商用點歌機的三種現場感 ——
  **🚪 包廂**（標準 KTV 手感）、**🎭 劇場**（殘響厚一點、回音收斂）、
  **🏟️ 演唱會**（大空間、長回音）。按一顆就同時設定好殘響與回音四個參數，
  之後仍可用下面的滑桿微調（微調後按鈕熄燈，表示已離開預設值）。
  柔化（防嘯叫）是場地相依的設定，不跟著風格走。
- **麥克風效果**：柔化（壓高頻）、殘響（空間感）、回音音量、回音重複次數、回音間隔（80~600ms）各自獨立調整；**乾聲** 一鍵全關（含和聲）。
- **🎶 和聲（雙聲部）**：見 4-2。
- **🎬 這首歌的字幕**：±2 秒微調**正在唱的這一首**的字幕時間（正值 = 字幕延後）。雙擊滑桿歸零，舞台端也可按 `←` `→`（Shift 微調 10ms、`0` 只歸零這一首）。調過的值**存在伺服器、綁這首歌**，下次唱同一首還在；沒有歌在唱時這條會關起來。喇叭本身的延遲（藍牙、HDMI）是另一個數字，在舞台按 `S` 調 —— 詳見 9-1 章。
- **音準導唱線**：切換舞台頂部的音準線顯示（舞台端也可按 `P`）。
- **🔁 練唱模式（A-B 循環）**：見下一章。

## 4-2. 和聲（雙聲部）

商用點歌機的 **HARMONY** 鍵：一個人唱，喇叭出來像兩個人。
系統把你的麥克風訊號即時移調，疊在旋律上方（或下方）當第二個聲部。

### 怎麼開

在調音台的 **🎶 和聲（雙聲部）** 區塊，直接按想要的聲部就會開始
（不必先按開關 —— 按聲部就等於「我要和聲」）：

| 聲部 | 聽起來像 | 什麼時候用 |
|------|----------|-----------|
| **三度** | 多一個人幫你唱高音 | 預設，最標準的 KTV 和聲 |
| **下三** | 多一個人幫你墊低音 | 主唱本身在高音區，往上疊會太尖 |
| **五度** | 空心、開闊 | 搖滾、台語歌的長音 |
| **八度** | 男聲厚度 | 想要厚但不想有和聲感；也是抒情慢歌的保守選擇 |
| **雙聲** | 上三度＋低八度一起 | 最接近「對唱」的聽感 |

**和聲音量** 滑桿控制第二個聲部多大聲。上限刻意設在主唱之下 ——
和聲蓋過主唱就不是和聲了。右上角的按鈕（已開啟／關閉中）一鍵開關。

### 為什麼我按了和聲卻沒聲音

依可能性排序：

1. **還沒開口唱**。和聲是把你的聲音移調再疊回去，沒人唱就沒有東西可疊。
   舞台徽章這時會寫「和聲 上三度（C 大調）**· 等你開口**」。
2. **現在是單人模式**。和聲屬於人聲，跟主唱吃同一個「人聲外放」開關 ——
   單人模式人聲不進喇叭，和聲自然也不會出來。
   要聽和聲請切 🔊 **多人模式**並使用**外接喇叭**。
3. **現在是前奏／間奏，或這一段沒有導唱旋律**（念白、饒舌）。
   三度與五度需要知道「現在是音階的第幾度」，沒有旋律可參照時會安靜；
   低八度不需要，任何時候都能疊。
4. **瀏覽器太舊**。移調用 AudioWorklet（Chrome 66+／Safari 14.1+），
   不支援的瀏覽器會在舞台上提示一次。

### 為什麼和聲不會走音

和聲的移調量是**照這首歌的調性在音階上算**的，不是固定升幾個半音。
以 C 大調為例：Do 的上三度是 Mi（升 4 個半音），但 Re 的上三度是 Fa（升 **3** 個半音）。
固定升 4 個半音會讓 Re 唱出 Fa♯ —— 那是別的調的音，聽起來就是走音。

調性由系統從這首歌的導唱旋律自動判定，並顯示在舞台右下角的 🎶 徽章上
（「和聲 上三度（**C 大調**）」）。**如果和聲聽起來怪，先看這個徽章** ——
判錯調就是唯一的原因。判不出調性的歌（旋律太少、念白曲、歌詞還沒處理好）
會自動退成低八度疊唱，因為八度在任何調都不會錯。

### 多人模式要注意

和聲會讓「進到喇叭的人聲」變多，也就是讓回授（嘯叫）的門檻降低。
如果開了和聲之後開始嘯叫：先把和聲音量調小，再照第 9 章〈麥克風有回音／嘯叫時〉處理。
緊急時舞台端按 `M` 一鍵切回單人模式，人聲與和聲會同時離開喇叭。

## 4-3. 對唱模式（兩支麥克風分別評分）

包廂裡那句「這首我們對唱，看誰分數高」。兩支麥克風各自計分，
唱完的結算畫面把兩個人的成績並排比出勝負。

### 怎麼開

1. **先把第二支麥克風接好**，並在**舞台端**按 `S` 開啟 🔊 音訊裝置面板，
   在「🎤🎤 第二支麥克風」選它的來源（這是那台機器的硬體接法，只能在舞台端選）：
   - **同一裝置的右聲道** —— 兩支麥克風接同一台立體聲音效介面／混音器，
     左聲道給 A、右聲道給 B。**包廂建議這一種**，也只有這條路能用真正的動圈麥克風。
   - **另一個輸入裝置** —— 兩支 USB 麥克風，各自是一個裝置。
2. 點歌台的調音台 → **🎤🎤 對唱模式** 按下開關（舞台端按 `D` 也可以）。
3. 想在畫面上看到名字就填 **A 麥 / B 麥的暱稱**（各 12 字內），
   計分板、浮字、成績紀錄都會用這個名字。

開起來之後，舞台右上角的計分卡會換成 **DUET SCORE** 兩條分數，
領先的那一位名字與分數會亮起來；音準線上會同時畫兩條軌跡
（**A 桃紅、B 青綠**，跟計分板名字前面的圓點同色）。

### 兩支麥克風請拉開距離

這是對唱模式唯一需要注意的事。兩支麥克風在同一個房間，
A 唱歌的時候 B 的麥克風也收得到 —— 這叫**串音**。
系統會比較兩支麥克風的音量來判斷「這一瞬間是誰在唱」，
只算真正在唱的那一位（兩個人一起唱時兩邊都算）。

所以：**各自靠近自己的嘴巴、兩支拉開一點**，判定就會很準。
兩支麥克風並排放在桌上對著同一個方向，誰也救不了 —— 那時兩支收到的訊號幾乎一樣。

判定被觸發時，被判成串音的那一列會**變淡並寫「串音靜音中」**。
如果你明明在唱卻看到這行字，就是上面那個問題。

### 唱完的對戰成績單

結算畫面中間會多一塊 **🎤🎤 對唱結果**：

- 上方一條勝負橫幅（🏆 誰勝出、領先幾分；差在 3% 以內顯示 🤝 平手）。
- 下方兩欄並排：各自的分數、等級、音準率、最大 COMBO 與**本曲個人最佳**。
  「刷新紀錄」比的是**自己**過去在這首歌的成績，不是跟對方比。
- 某一位有 30% 以上的時間被判成串音時，那一欄會標出比例 ——
  那不是唱不好，是兩支麥克風靠太近，這場的分數本身已經不公平。
- 再往下是 **🎼 段落對決**：哪一段是誰的主場（見下一節）。

### 段落對決：哪一段是誰的主場

「誰贏」只是一個數字，「副歌是誰撐起來的」才是包廂裡真正想知道的事。
所以兩欄成績下面還有一排長條圖，把**同一段落**兩位的音準率往中間對拉：

```
  66% ████████▌     副歌 1     ███████▏ 61%
  81% ██████████    副歌 2     █████▏   44%     ← 這一段偏得很明顯
```

- **左邊桃紅是 A、右邊青綠是 B**（跟舞台音準線上兩條軌跡同一組顏色），
  段落標籤釘在正中間。領先的那一邊百分比會亮起來。
- 上面一行比數：「小明 2 段・小美 1 段・平手 3 段」，
  再加上各自的 ⭐ **主場段落**（領先最多的那一段）。主場段落會跟著成績
  寫進評分歷史，點歌台與手機的結算通知也看得到。
- **分段接唱的段落不算勝負**：對唱歌曲本來就是主歌 1 你唱、主歌 2 我唱、
  副歌一起唱。只有一個人唱的段落標成「主唱」並變淡，另一邊顯示 `—` 而不是 0%——
  那一段本來就不是他唱的，畫成 0% 等於誣賴人。
- 同樣地，**跟一句不算對決**：B 只在副歌最後跟了一句、A 唱滿整段時，
  兩個音準率不是同一件事（跟一句的人只要那一句準就有 100%），
  這種段落會退成「這一段主要是 A 唱的」。
- 兩個人在同一段差不到 5 個百分點就算**平手**（百分比顯示成青色）——
  61% 對 59% 宣布主場只會幫你們製造爭吵。
- 段落多的歌最多列六段（優先列真的有對決的段落），並註明「另有 N 段未列出」。

### 只有一個人唱的時候

對唱開著、但另一支麥克風放在桌上沒人拿，是很常見的情況。
這時候系統**不會比勝負**（那不是比賽，是誤會），直接顯示有唱的那一位的單人成績單。

### 其他行為

- 兩支麥克風各有自己的**自動增益**（兩個人的距離不可能一樣），
  舞台的 `S` 面板在對唱模式下會多一條 **📶 B 麥電平** 表，開唱前先各自試音最保險。
- 兩支麥克風共用殘響、回音與「人聲外放」總開關 ——
  兩支的效果不一樣，聽起來會像兩個不同的房間在對唱。
- **對唱模式下和聲只疊在 A 麥上**：第二支麥克風本身就是第二個聲部，
  再疊機器和聲會變成四個聲部混在一起。
- 第二支麥克風開不起來（沒接、被別的程式占用、介面只給單聲道）時，
  舞台會直接顯示原因並把開關關回去 —— 不會讓按鈕停在「已開啟」而實際上沒在對唱。

## 4-1. 練唱模式（A-B 段落循環）

商用點歌機的「副歌重播」。在調音台的 **🔁 練唱模式** 區塊操作，
圈起來的區間是共享的 —— 包廂裡每台裝置看到的都一樣，舞台右下角會亮 🔁 徽章。

### 手動圈一段（A-B）

1. 歌播到想練的段落開頭，按 **A**。
2. 播到段落結尾，按 **B**。兩點都設好就**立刻開始循環**，唱到 B 點自動跳回 A 點。
3. 想停就按 **⏹ 停止循環**；要重圈按 **清除**。
4. A、B 按反了不用重來 —— 系統會自動對調。太短（不到 1 秒）的區間不會啟動循環。

### 一鍵副歌重唱

按 **副歌重唱**，系統會分析這首歌歌詞的重複結構，自動圈出副歌並開始循環，
同時跳到副歌開頭。找不到重複段落的歌（例如純演奏、歌詞沒抓到）會提示改用手動 A-B。

### 段落跳轉

練唱區塊下方會列出這首歌自動切好的段落：**前奏 / 主歌 1 / 副歌 1 / 間奏 1 / …／尾奏**。

- 點段落標籤 → 直接跳到那一段。
- 點段落右邊的 🔁 → 圈住那一段循環練唱。
- 底部的進度條也可以直接點一下跳過去。

### 備註

- 換下一首歌時 A-B 區間會自動清掉，不會帶到下一首。
- 跳轉不會沒收你已經唱到的分數；只有音準線上的舊軌跡會清掉（否則會畫出鬼影）。
- 開著循環時歌不會自然結束，也就不會出現唱畢結算 —— 練完記得先停止循環。

## 5. 系統設定（⚙️ 按鈕）

點歌台右上角的 **⚙️ 系統設定**。所有設定自動存進 `cache/settings.json`，重開機沿用。

### 🎚️ 開機預設調音

伺服器每次啟動時要套用的初始值：音樂／麥克風／導唱音量、升降 Key、
殘響、回音（音量／重複／間隔）、柔化、和聲、演唱模式、音準線顯示。

包廂調到滿意的手感之後把它設成預設，下次開機就不用再調一輪。
改完不想重開伺服器的話，按下方的 **⤵️ 套用預設到現在** 即可立刻生效。

### 🎶 和聲預設

- **開機就開和聲**：預設關。和聲是「加了才有」的效果，而且要多人模式才聽得到，
  開機就打開的話單人模式的使用者只會覺得這顆按鈕沒反應。
- **和聲聲部**：上三度／下三度／上五度／低八度／雙聲部，意義見 4-2。
- **和聲音量**：開機時的第二聲部音量。

### 🔁 公平輪唱

| 設定 | 說明 |
|------|------|
| 開機就開輪唱 | 預設關（先到先唱）。常客固定的包廂可以設成開機就開 |

輪唱的**開關**在點歌台的佇列標題旁邊（隨時可切、所有裝置同步），
這裡設的是「伺服器開機時的初始狀態」。規則與注意事項見 2 章的〈公平輪唱〉。

「今晚唱過幾首」歸零的門檻用的是下面 📦 整晚打包的
**「相隔幾小時算換一場」**（預設 6 小時）—— 系統裡「一場」只有一個定義。

### 🎫 每人待唱上限（點歌額度）

| 設定 | 說明 |
|------|------|
| 每人待唱上限 | 0 = 不限（預設）。最多 20 首。算的是「同時排幾首」，不是今晚總共 |

跟輪唱是**獨立的兩條規則**（輪唱管順序、額度管量），可以只開其中一條。
這裡設的是「伺服器開機時的初始值」，臨時要改在點歌台佇列標題旁邊用 −／＋ 就行。
規則與注意事項見 2 章的〈每人待唱上限〉。

### ⏱️ 包廂計時（歡唱時間）

| 設定 | 說明 |
|------|------|
| 啟用包廂計時 | 預設**關**。關著的時候點歌台不會出現倒數 |
| 一場多久 | 預設 180 分鐘（10 ~ 1440）|
| 第一首歌自動開錶 | 預設開。免得三小時後才想起來沒按開始 |
| 第一次提醒 | 剩幾分鐘時提醒一次，預設 10。**0 = 不提醒** |
| 最後召集 | 第二次提醒，預設剩 3 分鐘。**0 = 不提醒** |
| 時間到怎麼辦 | **唱完這一首再停**（預設）／只提醒，不停歌 |
| 續時一次加 | 預設 30 分鐘（5 ~ 240）|

**為什麼沒有「立刻停掉這一首」這個選項**

商用點歌機時間到就切歌。被切掉的人正站在包廂中間、麥克風在他手上、
剛唱到副歌最高的那一句，然後畫面黑掉 —— 他不會覺得「時間到了」，
他會覺得「機器在我唱到一半的時候把我關掉」。

讓它唱完最多就是超時三到五分鐘，而且是講得出來、提醒過的；
停在副歌那一句則是不可預期的難堪。所以這裡只有「唱完這一首再停」與
「只提醒，不停歌」兩個選項。

操作方式與時間到之後的行為見 2 章的〈包廂計時〉。

### 🎤🎤 對唱模式

| 設定 | 說明 |
|------|------|
| 開機就開對唱 | 預設關。第二支麥克風不是每台機器都有 |
| 串音判定門檻 | 兩支麥克風的音量差超過幾 dB 就只算大聲的那一位（3~24 dB，預設 9） |

**門檻怎麼調**：看結算畫面顯示的「被判為串音的時間比例」。

- 一直有人被判成串音（> 30%）而他確實在唱 → **門檻調高**，或把兩支麥克風拉開。
- 有人明明沒唱卻一直有分數 → **門檻調低**（房間小、喇叭大聲時串音更嚴重）。
- 調太高的副作用是「唱得比較收的那一位」會被連帶判成串音，整首都沒分數。

### 🔊 自動音量平衡（EBU R128）

> 解決「上一首震耳欲聾、下一首要把音量轉到底才聽得到」。

- YouTube 上的來源響度差距很大：官方 MV 母帶常壓到 -8 LUFS，
  個人上傳的現場版可能只有 -22 LUFS —— 中間差了 14 dB。
- 每首歌在處理流水線的最後會量一次 **整合響度（integrated loudness，
  ITU-R BS.1770-4 的 K 加權 + 雙重閘門）**，把結果存進 metadata；
  播放時自動補到同一個目標響度，所以每首聽起來一樣大聲。
- **目標響度** 預設 -14 LUFS（串流平台通用值）。想更安靜就往負的調。
- 增益夾在 ±12 dB，而且會做峰值保護（拉完不超過 -1 dBFS），不會把歌拉到破音。
- 量不到響度的歌（檔案損壞、近乎靜音）一律 0 dB —— 寧可不動，也不要亂調。
- **啟用前就快取好的舊歌** 不用重跑流水線：第一次播放時會現場量一次並補寫回 metadata。

### 🎚️ 導唱自動淡出（Guide Vocal Auto-Ducking）

> 解決「導唱開著怕唱不出自己的味道，關掉又怕忘詞」。

- 導唱人聲不再只有開／關兩檔：**唱穩了它自己退到背景，走音或忘詞時立刻回來扶一把**，
  跟商用機的「導唱漸弱」是同一件事。
- **淡出深度** 決定最多壓多少：預設 60%（最低降到原本的 40%）。
  上限 95%，**永遠留一點導唱在背景當安全網**，不會整段消失。
- 退場是慢慢來的（約一兩秒），回來是立刻的（約 0.2 秒）—— 救援不能遲到。
- 命中率看的是最近約一句歌詞的長度，唱錯一兩個字不會把導唱整個叫回來；
  在門檻附近游移時維持現狀，不會忽大忽小。
- 每首歌開頭會先觀察 3 秒才可能開始退場（第一個音唱準不算穩定）。
- 前奏、間奏不作用；**把調音台的「導唱人聲」轉到 0（純伴奏）時整個功能自動停用**。
- 退場時舞台右下角會亮出 🎚️ **導唱自動淡出 XX%** 徽章，
  讓台上的人知道那是機器在讓路，不是設備出問題。

### 🎤 麥克風自動增益（Mic AGC）

> 解決「換人唱就要重調麥克風音量」。

- 打開之後機器會**自己把每個人的收音電平拉到同一個目標**：
  上一位貼著麥克風吼、下一位離 20 公分小聲哼，都不用再去動滑桿。
- **目標收音電平**（預設 -18 dBFS）：往 -6 調會更大聲、更貼近削峰邊緣（多人模式也更容易回授）；
  往 -30 調比較保守。多數包廂用預設值就好。
- **安靜的時候絕對不會加大**。這是刻意的：房間底噪照著「拉到目標」算下去會一路加到上限，
  第一個字進來就爆掉，多人模式還會當場嘯叫。
- **要降立刻降、要升慢慢升**：突然大聲（貼麥克風、尖叫）0.25 秒內就壓下來；
  變小聲則花約 3 秒慢慢補回去，句與句之間的空隙才不會把底噪一起抬起來。
- 加成最多 **+9 dB**、削減最多 **-12 dB**；切到**多人模式時加成上限收到 +6 dB** ——
  人聲從喇叭出來時，每多加 1 dB 就離回授近 1 dB。
- 補償超過 ±1 dB 時舞台右下角會亮 🎤 **麥克風自動增益 ±X.X dB** 徽章。
- **不會影響評分**：音準偵測抓的是麥克風原始訊號，所以自動增益調得再多，
  分數還是照你實際唱的算。
- **調音台的麥克風音量滑桿仍然有效**，兩者是分開的兩層：
  自動增益負責「把不同人拉到差不多」，滑桿負責「你想要多大聲」。

**先試音再開唱**：舞台螢幕按 `S`（或右上角 ⚙️）開啟音訊面板，
裡面有一條 **📶 收音電平** 表：

| 表頭 | 意思 | 該做什麼 |
|------|------|----------|
| 一直貼在左邊（灰色） | 沒收到聲音，或唱得太遠 | 檢查麥克風有沒有插好／選對裝置／靜音鍵，或把麥克風拿近 |
| 中間偏右（青色） | 正常 | 不用動 |
| 一直頂到右邊（粉紅） | 太近，快削峰了 | 拿遠一點，不然爆音救不回來 |

右邊的數字就是機器現在幫你加／減多少 dB。

### 🌙 排程預處理

### 🌌 情境背景

沒抓到 MV 的歌不會是黑畫面，改放會跟著音樂動的情境視覺（見第 8 章）。

- **情境背景**：
  - `沒有 MV 時`（預設）— 只有在這首歌沒有可用的 MV 時才出場。
  - `一律使用` — 有 MV 也不放，整場都用情境背景（覺得 MV 讓人分心、
    或不想把版權畫面放在牆上時用這個）。
  - `關閉` — 沒有 MV 就是黑畫面。
- **背景主題**：極光、星空、霓虹、海洋、燭火，或 `自動（依歌曲）` ——
  自動會依歌曲**固定**挑一個，同一首歌每次都是同一個背景。
- **背景亮度上限**：覺得背景跟字幕搶就往下調（最低 30%）。
  背景的亮度變化本來就有限速，不會閃。

### 🎙️ 錄唱回放

| 設定 | 預設 | 說明 |
|------|------|------|
| 錄唱回放 | **關閉** | 打開之後，下一首開始唱就會錄 |
| 最多保存幾首 | 50 首 | 超過從最舊、沒標記保留的那一筆開始刪 |
| 錄音配額 | 512 MB | 同上。錄音跟歌曲快取共用磁碟，所以一定要有上限 |
| 唱不到幾秒就不留 | 10 秒 | 算的是「有人在唱」的時間，不是歌放了多久 |

- 預設關閉是刻意的：錄音錄到的是包廂裡所有人的聲音。
- **關掉的當下**就會停手並丟掉手上正在錄的那一段，不是等這首唱完。
- 錄好的在點歌台的「🎙️ 錄唱回放」分頁（見第 2 章「錄唱回放」）。
- 一首 3 分鐘的錄音大約 1~2 MB。預設配額大約可以存滿 50 首。

### 🔗 錄音分享

| 設定 | 預設 | 說明 |
|------|------|------|
| 允許分享錄音 | 開啟 | 關掉之後 🔗 分享鈕會直接說明沒有開放 |
| 連結有效時間 | 24 小時 | 最長 30 天。**沒有「永不過期」** |
| 下載幾次就失效 | 0（不限） | 只算真的按下載，播放與拖進度條都不算 |

- 分享連結**不需要登入**就打得開（掃 QR 的人不會先登入），
  所以時效是唯一的安全邊界 —— 這也是為什麼沒有「永不過期」。
- 送錯人隨時可以撤銷，按下去立刻生效。
- 連結指向這台機器的網址，**預設只在同一個網路裡打得開**；
  要讓人帶回家聽請設 `KARATUBE_PUBLIC_HOST`（見 DEPLOYMENT.md）。

### 🎧 錄音轉 MP3

| 設定 | 預設 | 說明 |
|------|------|------|
| 錄音轉 MP3 | 開啟 | 關掉之後 🎧 MP3 鈕不出現（分享頁上也不出現） |
| MP3 位元率 | 192 kbps | 96～320。再高在車機上也聽不出差別，只是檔案變大 |

- 為什麼要這個：錄音是**瀏覽器**錄的（Chrome/Firefox 給 webm、Safari 給 mp4），
  在包廂裡播沒問題，但車上的 USB、長輩的舊手機、傳進群組直接點開的那些地方
  多半只認 MP3。
- **按下去才轉**，不是錄完就轉 —— 那會跟正在放歌的 CPU 搶資源。
  第一次按要等幾秒（按鈕會變成「⏳ 轉檔中…」），之後是秒回。
- 轉好的 MP3 是**可以丟的快取**：有自己的上限（錄音配額的 1/4，**額外**佔用），
  滿了從最久沒用到的那一份開始刪，**永遠不會擠掉任何一次演唱**。
  想手動清就按清單上的「🧹 清除 MP3 快取」—— 錄音一個都不會動。
- 需要機器上有 **ffmpeg**（而且要含 libmp3lame）。沒有的話清單上會直接寫出來，
  裝好之後不必重開伺服器。

### 📦 整晚打包

| 設定 | 預設 | 說明 |
|------|------|------|
| 相隔幾小時算換一場 | 6 小時 | 相鄰兩次演唱超過這個間隔，就算是不同的一場 |

- 一場**不是照日曆日期**算的：包廂的一場常常是「九點唱到凌晨兩點半」，
  照日期切會把它剖成兩半，而且唱到最嗨的後半會被標成「隔天」。
- 調**小**（例如 2 小時）：中間休息很久的一晚會被切成兩場。
- 調**大**（例如 12 小時）：下午那一輪跟晚上那一輪會被算成同一場。
- 打包列在「🎙️ 錄唱回放」分頁最上面，顯示最近三場（見第 2 章「整晚打包」）。

### 📺 舞台訊息（跑馬燈）

| 設定 | 說明 |
|------|------|
| 啟用舞台訊息 | 預設**開**。關掉之後那顆鍵還在（會變暗），但送不出去 |
| 每則停留 | 每一則在螢幕上停留幾秒，多則輪播用（3 ~ 30 秒，預設 8）|
| 幾分鐘後消失 | 預設 10 分鐘（1 ~ 240）。要更久請用「📌 釘住」送 |
| 沒在播歌時用大字卡 | 預設開。關掉的話一律走上緣那一條 |

**為什麼沒有「永不過期」**：散場之後還掛在螢幕上的生日祝福，
是下一桌客人看到的第一個東西。釘住的上限是 4 小時。

**為什麼沒有「播歌時也用大字卡」**：那正是這個功能要避免的畫面 ——
蓋住的是正在唱的那個人。做成選項等於把它留在那裡等人選到。

### 🔔 服務鈴（包廂呼叫櫃檯）

| 設定 | 說明 |
|------|------|
| 啟用服務鈴 | 預設**開**。關掉之後那顆鍵還在（會變暗），但按不出單 |
| 開多久算過期 | 一張沒人處理的單過多久自動關閉（5 ~ 480 分鐘，預設 45）|
| 有新的單時提示一聲 | 預設開。櫃檯與點歌台是同一台時可以關掉（自己按的鈴自己響很吵）|

**為什麼是「過期」而不是「刪掉」**：默默刪掉的話，客人以為單子還在跑，
而櫃檯那邊什麼都沒有。標成過期至少雙方看到的是同一件事。

**為什麼沒有「每個人的額度」**：服務鈴不是點歌 —— 一張單併掉所有重複的按壓，
所以根本不會被一個人洗版，也就不需要擋任何人。

操作方式見第 2 章〈服務鈴〉。

### 🔒 櫃檯管理鎖（放到店裡才需要）

把「機器的事」跟「唱歌的事」分開的一組櫃檯密碼。**預設關著** ——
家裡唱歌不需要它，開著只會多一道自己人要輸入的密碼。

**怎麼開**：右上角 **🔒 櫃檯管理** → 輸入 4–8 位數字 → 設定密碼。
設完會**立刻上鎖**（設密碼的人已經知道密碼，重打一次是三秒鐘的事）。

| 鎖起來的（要櫃檯密碼） | 永遠不鎖的 |
|---|---|
| 刪除曲庫歌曲、重新處理 | 點歌、插播、切歌、重唱、拖曳排序 |
| 系統設定（這一整頁）、恢復原廠 | 調音量、效果、升降 Key、練唱模式 |
| 排程預處理（新增／取消／清空）| 評分、結算、我的成績 |
| 清空點唱排行、清空已唱歷史 | 收藏、查歌（注音／歌號／歌星）|
| 清空所有錄音、清空 MP3 快取 | 錄自己那一次、刪自己那一次、分享 |
| 包廂計時（開始／續時／暫停／結束）| 🎲 來一首、自動接歌 |
| 舞台訊息（發布／刪除／全部撤掉）| 按服務鈴、自己取消服務需求 |
| 服務鈴的櫃檯端：👀 櫃檯收到、✅ 完成、清除紀錄 | 看清單、看排行、看設定（唯讀一律不鎖）|
| 重設輪唱順序 | |

**唱歌的事一條都不鎖**是刻意的：鎖錯一條的代價不是「多按一次密碼」，
是整個晚上沒有人能唱歌，而櫃檯不一定在。

| 操作 | 說明 |
|------|------|
| 🔓 解鎖 | 打密碼。解開的是**這台裝置**（櫃檯的平板解開了，包廂的手機還是鎖著的）|
| 🔒 立刻上鎖 | 做完事按一下。**不需要密碼** —— 關門不需要鑰匙 |
| 閒置自動上鎖 | 預設 15 分鐘（1–240）。櫃檯忘記上鎖是常態，所以它自己會鎖回去 |
| 換密碼 | 要先解鎖或輸入目前的密碼。換完立刻回到上鎖 |
| 停用管理鎖 | 回到家用模式：所有動作都不需要密碼 |

**被擋下來會怎樣**：畫面直接跳出密碼面板，並告訴你被擋的是**哪一個動作**；
解鎖之後**剛剛那個動作會自動接著做完**，不用再按一次。

**密碼錯了**：前三次只是提示，之後要罰站（5 / 15 / 60 / 180 / 300 秒遞增，
上限五分鐘）。畫面會分開講「密碼錯誤，再錯 2 次就要罰站」與
「密碼錯太多次，請等 15 秒再試」—— 罰站中連正確的密碼都會先被擋下來。

**忘記密碼怎麼辦**（面板下方也印著這兩行）：

1. 在伺服器上設環境變數 `KARATUBE_STAFF_PIN=<新密碼>` 後重開，用它解鎖
   （它一直是有效的備用鑰匙，設了它本身不會啟用這把鎖）。
2. 或把 `cache/staff_lock.json` 刪掉（會一併清掉自動上鎖設定）。

兩條都需要**碰得到伺服器那台機器** —— 這把鎖真正的安全邊界就是它放在哪裡。

> ⚠️ **這把鎖擋的是誤觸與跨場次的破壞，不是惡意。** 包廂的 Wi-Fi 上沒有身分，
> 任何一支手機都可以假裝是另一支。不要因為設了密碼就把這台機器直接開到公網上。

**伺服器重開之後一律是上鎖狀態**（解鎖只存在記憶體裡）：重開代表有人碰得到
那台機器，那時候的正確狀態是鎖著。

### 情境背景（沒有 MV 的歌）

有些歌抓不到 MV（只有音訊），有些歌抓到的其實是**一張圖配四分鐘音訊**
（YouTube 上大量的「音樂版／歌詞版」上傳都是這樣）。這兩種情況舞台都不放黑畫面，
改放會跟著音樂動的情境視覺，底圖是這首歌的封面放大模糊。

- **靜態圖會被認出來**：舞台每 1.2 秒偷偷取樣一次畫面，連續幾筆幾乎沒有差異
  就判定「這是一張圖」，換成情境背景。判定大約 5 秒完成，通常還藏在片頭卡後面。
  真的會動的 MV 一秒內就會被認出來，絕對不會被換掉。
- **一旦決定就不會再變**：唱到一半背景在 MV 與情境之間來回切，比哪一種都糟。
- **沒有歌在播的時候**也是情境背景（商用點歌機的待機畫面），只是動得比較慢。
- **不會閃**：背景的亮度變化有速度上限，鼓點只推動粒子與波形、不會把畫面打亮。
- 主題、亮度與「要不要用」在 **⚙️ 系統設定 → 🌌 情境背景**。
- 舊機器跑不動時它會自己降畫質（背景永遠讓路給字幕與評分），不用手動調。

### 唱畢總評分結算

- 整首唱完，舞台自動亮出成績單：**總分**（滾動動畫）、**SSS~C 等級**、**音準率**、**最大 COMBO**。
- 下方顯示 **本曲個人最佳** 與 **擊敗全場 XX% 的演唱**；打破紀錄會顯示「🎉 刷新個人最佳！」。
- 結算畫面停留 9 秒（可在 **⚙️ 系統設定 → 舞台演出** 調整）後自動進下一首；**點一下畫面可直接跳過**。
- 沒人開口唱（純放歌）不會出結算畫面，直接接下一首。
- 隱藏音準線（`P`）時評分照樣進行，結算不受影響。
- 成績存在 `cache/score_history.json`；點歌台與手機端會同步收到「🏁 XXX：1234 分（S）」通知。

### 段落評分（哪一段唱得最好／最差）

結算畫面中間多一塊 **📊 段落表現**：

- 每一段（主歌 1、副歌 1、主歌 2…）一條長條，右邊標命中率百分比。
- 上方點名 **💯 最佳段落** 與 **📈 待加強**（最佳那條標黃、待加強那條標粉）。
- 段落是系統從歌詞的重複結構自動切出來的（和練唱模式的段落膠囊同一份），
  不需要事先標記。前奏、間奏、尾奏沒有導唱旋律，不列入。

什麼時候不會點名段落：

- **整首唱得很平均**時（最佳與最差差不到 5 個百分點）只顯示長條圖，
  上方寫「整首表現平均，沒有明顯拖分的段落」—— 不會為了有話講而硬挑一段來嫌。
- **唱得太短的段落**（導唱旋律不到約半秒）不參加評分，也不會被點名成最差。
- **可評分的段落不到兩段**（這首沒歌詞、或只唱一段就切歌）整塊收起來，
  總分與等級照常顯示。

搭配練唱模式很好用：把副歌用 A-B 循環唱三輪，長條圖上的副歌命中率是三輪累計的比例，
可以直接看出練起來了沒有。最佳／待加強的結論也會寫進成績歷史，
所以「這首歌我老是同一段唱壞」看紀錄就知道。

### 跨場次趨勢（這首歌你一向如何）

段落長條圖下方，同一首歌唱滿三次之後會多一塊 **📊 近 N 次**：

- 一句結論（「🏠 主場 主歌 1（一向高 12 個百分點）　📈 待加強 副歌 1（一向低 13 個百分點）」）
  加一張中線是「你自己的平均」的長條圖。
- 上面那張段落長條圖講的是**這一次**，這一塊講的是**每一次** ——
  今天副歌掉了可能只是沒接上氣，一向掉才是要練的地方。
- 這份趨勢**含剛唱完的這一次**：今天明明唱好了副歌，畫面還說副歌是你的弱點，
  是最傷人的那種不一致。
- 還沒唱滿三次時顯示「再唱 N 次就能看出你在這首歌一向強在哪一段」，
  不是空白 —— 免得以為這塊壞了。
- 整首都唱得很平均時會明講「沒有明顯弱點」（那是好消息，不是沒資料）。
- 對唱模式則是兩位各一句話，不畫長條圖 ——
  同一個畫面已經有段落對決的對拉長條圖了，再疊兩張九秒內沒有人看得完。
- 完整的趨勢圖在點歌台的「📊 我的成績」分頁，唱完可以慢慢看。

### 導唱獨立度

段落長條圖下方會多一行 **🎚️ 導唱獨立度 XX%**：這首歌有多少比例的時間，
導唱是自動淡出的（也就是你不需要它帶）。

- 這個數字比總分更能看出進步：分數會被歌難不難影響，
  但「上週副歌整段靠導唱，這週導唱退場了七成」是很直接的回饋。
- 導唱本來就沒開（純伴奏）、或這輪唱不到 20 秒不足以判斷時，**這一行不會出現** ——
  寧可不顯示，也不給一個沒有意義的數字。

### 麥克風建議

自動增益整首一直在大幅補償時，結算會多一行能直接動手的建議：

- 平均 **+3 dB 以上** → 「麥克風可以拿近一點，音色會更紮實」（軟體能加的量有上限，
  加到底只是把底噪一起放大）。
- 平均 **-3 dB 以下**，或中途啟動過削峰保護 → 「拿遠一點」（貼太近音色會悶，而且爆音救不回來）。
- 差不到 3 dB 就不出現 —— 每首歌都跳一行建議會變成沒人看的雜訊。

## 9-1. 字幕對不上怎麼辦

先花十秒鐘分辨是哪一種 —— **三種原因的解法完全不同**，用錯手段會越調越糟：

| 症狀 | 原因 | 怎麼修 |
|:---|:---|:---|
| **每一首歌都差不多晚（或早）一樣多** | 喇叭／電視的輸出延遲 | 舞台按 `S` → **🕐 本機延遲補償** |
| **只有這一首對不上，其他都好** | 這首歌抓到的歌詞版本不同 | 播放中按 `←` `→`，或調音台的「🎬 這首歌的字幕」 |
| **開頭對，越後面越歪** | 抓到的是別的版本（Live／加長／變速上傳），**速度**不一樣 | 調偏移救不了 → 「🗂️ 快取管理」→ **🔄 重算歌詞** |

### 這首歌的字幕（最常用的那一個）

播放中在舞台按 `←`（字幕提前）`→`（字幕延後），一次 50ms、按著 `Shift` 一次 10ms；
手機或點歌台則用調音台裡的「🎬 這首歌的字幕」滑桿。

- 調過的值**跟著這首歌走**：所有裝置共用、**下次唱同一首直接套用**，
  連「重新處理」都不會洗掉它。曲庫會愈唱愈準。
- `0` 只歸零**這一首**，喇叭的延遲補償不動。
- **沒有歌在唱時按方向鍵不會改到任何東西**（只會跳一行說明）——
  待機時沒有東西可以對齊，這時候調本來就沒有意義。

### 這台機器的延遲（換了喇叭才要動）

舞台按 `S` 打開音訊設定面板，最下面那一列 **🕐 本機延遲補償**（`−` `＋` 一次 10ms）。
瀏覽器已經自動扣掉一部分延遲（畫面上會寫「已自動補償 XX ms」），
藍牙喇叭、外接混音器、HDMI 電視量不到的那一段才要手動補。

**這個數字只屬於那一台舞台機**（存在那台瀏覽器裡），不會跟著歌走、
也不會影響別台裝置 —— 手機聽不到舞台的喇叭，所以手機上看不到這個設定。

### 「按 L 設成本機基準」是什麼意思

如果你發現**連續好幾首都往同一邊調了差不多的量**，那多半不是歌詞的問題，
是喇叭。舞台會主動提示一行「這比較像喇叭的延遲，按 `L` 可以設成本機基準」。

按下去之後機器做兩件事（會先問你一次）：本機基準加上那個量，**同時把伺服器上
每一首校正過的歌各減掉同樣的量**。總效果不變，但以後新的歌就不必再各自調了。
第二台舞台機不會跟著變（它有自己的音訊路徑），要自己再調一次。
反向再做一次就回得去。

### 為什麼調字幕不會影響分數

導唱音符是從人聲軌抽出來的，跟音訊對得死死的；歌詞則是另外抓來對齊的。
所以機器內部走兩條時間：**評分與音準線**用音訊那一條（只扣喇叭延遲），
**字幕**才用加上這首歌偏移的那一條。把某一首的字幕往後拉 300ms，
不會讓那一首的音準率變差。

### 看得出哪幾首歌的字幕有問題

「🗂️ 快取管理」每一列都有一個對齊徽章：

| 徽章 | 意思 | 要不要動它 |
|:---|:---|:---|
| **對齊良好** | 抓到的歌詞對得很準 | 不用 |
| **對齊勉強** | 分數偏低，可能是不同版本 | 覺得怪再重算 |
| **對齊可疑** | 低於信任門檻，很可能抓到同名的別首歌 | 建議重算 |
| **聽寫字幕** | 找不到歌詞檔，改用人聲聽寫（時間軸通常準、**用字可能不對**）| 想要正確歌詞就重算 |
| **沒有歌詞** | 什麼都沒抓到，畫面上只有佔位文字 | 重算，或重新處理 |
| **對齊未知** | 這首歌是這個功能加進來之前處理的 | 想知道就重算一次 |

滑鼠停在徽章上會看到細節（對到哪一首、分數、人聲覆蓋率、變速校正、行數）。
被人工校正過的歌會多一個 `🎬 +250ms` 的標記。

### 🔄 重算歌詞 vs 🔁 重新處理

| | 🔄 重算歌詞 | 🔁 重新處理 |
|:---|:---|:---|
| 做什麼 | 只用現有的人聲軌重新對一次字幕 | 砍掉整首重新下載＋AI 分離＋聽寫＋音準 |
| 多久 | 通常十幾秒 | 幾分鐘起跳 |
| 那首歌會不見嗎 | 不會 | 會（跑完才回來）|
| 什麼時候用 | 字幕歪掉、抓錯歌詞版本 | 檔案缺漏、伴奏本身有問題 |

**重算前要知道的三件事**（確認框也會講）：要**下一次播放**才會套用；
這首歌的跨場次段落趨勢會從頭累積（曲式可能變了）；
**這首歌手動校正過的字幕偏移會被一併清掉** —— 那個數字是為舊的那份歌詞調的，
歌詞換了它最可能變成錯的。

重算完成後畫面會講出新舊分數（例如「對齊可疑 → 對齊良好（0.210 → 0.812）」），
你才知道這次到底有沒有變好。演唱中或還在佇列裡的歌不能重算。

## 9. 常見問題

**Q：客人的手機會不會把曲庫刪掉／把設定改掉？**
在家裡不會有人這樣做，放到店裡請開 **🔒 櫃檯管理鎖**（右上角）：
刪曲庫、改設定、清排行、包廂計時、舞台訊息都會需要櫃檯密碼，
而點歌、切歌、調音效這些永遠不需要。設定方式見第 5 章。

**Q：按了某個按鈕，跳出「需要櫃檯解鎖」？**
那是櫃檯管理鎖擋下來的（訊息裡會寫是哪一個動作）。請櫃檯來輸入密碼 ——
解鎖之後你剛剛按的那個動作會自動接著做完。唱歌相關的動作不會被擋，
如果被擋的是點歌或切歌，那是個 bug，請回報。

**Q：喇叭一直嘯叫（回授）怎麼辦？**
把「🎙️ 麥克風」拉到 0 或按調音台的「乾聲」，並切回 🎧 單人模式。筆電內建麥克風 + 筆電喇叭的組合請一律使用單人模式。

**Q：字幕跟人聲對不上？**
先分辨是哪一種（見 9-1 章）：**每一首歌都差不多一樣多**是喇叭的延遲
（舞台按 `S` → 🕐 本機延遲補償，藍牙通常要 +100~+300ms）；
**只有這一首**是歌詞檔的問題（播放中按 `←` `→`，或用調音台的「🎬 這首歌的字幕」）。
**越唱越歪**（開頭對、後面越差越多）調偏移救不了，那是抓到了不同版本的歌詞 ——
到「🗂️ 快取管理」按那首歌的 **🔄 重算歌詞**。

**Q：處理一首新歌要多久？**
有 NVIDIA GPU 大約 1~3 分鐘（視歌曲長度）；純 CPU 會明顯更久。處理過的歌會快取，之後秒播。

**Q：想把副歌反覆練熟怎麼做？**
開調音台的 **🔁 練唱模式**，按「副歌重唱」讓系統自動圈出副歌；
想練別段就播到定點按 **A**、**B** 自己圈，或直接點下方的段落膠囊。練完記得按「停止循環」。

**Q：快取佔太多空間？**
在 **⚙️ 系統設定 → 快取** 設一個上限並開啟自動清理，超過就會從最舊的歌開始刪
（演唱中與佇列裡的不刪）。想手動挑著刪，用「🗂️ 快取管理」分頁。
歌曲快取實體位置在 `cache/songs/`。

**Q：導唱人聲自己變小聲了，是壞了嗎？**
不是，那是 **導唱自動淡出**：你唱穩的時候導唱會讓路，唱不下去它會自己回來。
舞台右下角亮著 🎚️ 徽章就是這個狀態。不想要的話在
**⚙️ 系統設定 → 導唱自動淡出** 關掉，或把深度調成 0%。

**Q：換人唱就要重調麥克風音量，很煩？**
**⚙️ 系統設定 → 麥克風自動增益** 預設就是開的，機器會自己把每個人拉到差不多的音量。
如果覺得整體太小聲／太大聲，調「目標收音電平」（往 -6 更大聲、往 -30 更小聲）。
在多人模式（人聲外放）容易嘯叫時，可以把它關掉 —— 自動增益最多加 +6 dB，
但回授邊緣上那 6 dB 就是差別。

**Q：舞台的 📶 收音電平表都不動？**
麥克風沒被瀏覽器抓到。先點一下舞台畫面允許麥克風權限，再按 `S` 從
「🎙️ 麥克風」下拉選對裝置；筆電要確認實體靜音鍵沒有開。
表頭有動但一直貼在左邊，就是唱得太遠或麥克風增益本身太低。

**Q：每次唱新歌都要等好幾分鐘，有辦法先準備好嗎？**
有。用「🌙 排程預處理」分頁把整張播放清單貼進去，機器會在半夜（預設 02:00–06:00）
自己跑完，隔天點下去全部是「⚡ 快取秒播」。有人在唱歌時它會自動讓開，
不會跟現場搶資源。

**Q：排程排了但一直沒開始跑？**
看分頁上方那行狀態，它會直接寫原因：
「等待排程時段」＝還沒到開工時間（想現在跑就按 **⚡ 立即開始**）；
「現在有人在唱歌」＝等舞台空下來；「排程預處理已關閉」＝去 ⚙️ 系統設定打開；
「沒有待處理的歌曲」＝這批其實都已經在曲庫裡了。

**Q：排程跑到一半機器重開，要重貼嗎？**
不用。任務存在 `cache/batch_jobs.json`，重開後會接著跑，
中斷在半路的那一首會重跑一次（半成品不留）。

**Q：畫面說「已經排了 N 首待唱」，我點不了歌？**
包廂開了 **🎫 每人待唱上限**（佇列標題旁邊看得到現在的上限）。
上限算的是「同時排幾首」，所以**等自己其中一首唱完，那一格就空出來**了，
不必找人來解鎖。那句提示也會告訴你下一首排在第幾位。
不想限制的話，按中間的 🎫 標籤切回「不限首數」。

**Q：我明明只點了一首，卻說我排了三首？**
你沒有設暱稱。**沒設暱稱的所有人共用同一份額度**（機器分不出誰是誰），
那三首是整桶加起來的。到右上角 👤 取個暱稱，就有屬於自己的額度了。

**Q：把每人待唱上限調低，會把已經排好的歌刪掉嗎？**
不會，一首都不會動。調低（或中途才打開）只會讓超過的人在降回上限以下之前
點不了新的歌，已經在佇列上的照常唱完。

**Q：歡唱時間到了，正在唱的那一首會被切掉嗎？**
不會。它會唱完，唱完之後機器才停下來、不再播下一首。所以最壞的情況是超時
一首歌的長度，而你在剩十分鐘的時候就已經被提醒過了。
（設定頁裡刻意沒有「立刻停掉」這個選項。）

**Q：時間到了，佇列裡排好的歌會不會不見？**
一首都不會。停下來的是播放，不是資料 —— 在點歌台按「＋30 分」續時，
機器會自己接著播下一首，順序也不會變。

**Q：時間到之後點不了歌？**
對，時間到之後點的歌不會播（連 ⚡ 插播也一樣），所以直接擋下來。
續時就可以接著點、接著唱。真的不想再被時間管的話，
按點歌台右上角的倒數選「結束計時」，之後就不會再因為時間到而停止播放。

**Q：每首歌音量差很多，一直要調音量？**
在 **⚙️ 系統設定 → 自動音量平衡** 確認已啟用（預設就是開的），
所有歌會自動補到同一個目標響度（預設 -14 LUFS）。
啟用前就快取好的舊歌，第一次播放時會現場量一次，之後就記住了。

## 10. 開發者：跑測試

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -v          # 後端單元 + API 測試（583 條）
ruff check .                        # Python lint（設定在 ruff.toml）
for f in frontend/js/*.js frontend/tests/*.js; do node --check "$f"; done   # 前端語法檢查
node --test "frontend/tests/*.test.js"   # 前端純邏輯單元測試（298 條，免 npm install）
```

前端測試用 Node 內建的測試執行器，不需要 `npm install`，
但路徑要傳 glob 字串（傳目錄會被 `node --test` 當成模組去 require）。

CI（GitHub Actions）會在每個 PR 自動跑以上檢查。
