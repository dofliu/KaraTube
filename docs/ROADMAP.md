## 💡 後續想做的（非必要，想到就補）

### 系統
- [ ] 多包廂（一台伺服器帶多組舞台與佇列）
- [x] 自動接歌（待機時自己接一首）*(2026-09-20)* —— 商用點歌機的「沒有安靜這個
      狀態」。功能本身三行就寫得完（隨機挑一首播），難的全部在**機器什麼時候
      該閉嘴**：只挑已經備好的歌（不趁大家在聊天時去下載新歌把 CPU 吃光）、
      空了要先等二十秒（別跟正在找歌的人搶）、有人點歌時看「有沒有人已經唱
      進去了」再決定當場讓位還是唱完（45 秒為界）、連著接三首沒人接手就安靜
      （沒有人點歌通常代表沒有人在了）。而且機器接的歌不算任何人的一首 ——
      尤其不進點唱排行，否則照排行挑歌、播出來又計進排行，那條排行三個晚上
      之後就只剩機器自己的回音。詳見 CHANGELOG 1.18.0。

### 查歌
- [x] 歌星注音索引（歌星查歌）*(2026-09-19)* —— 商用點歌機的「歌星點歌」。
      難的不是鍵盤（跟歌名查歌共用同一副），是**誰跟誰是同一個人**：同一位歌星
      在曲庫裡會長出「周杰倫」「Jay Chou」「周杰倫 Jay Chou」三種寫法，不併的話
      清單上會出現三個周杰倫，每一個手上只有他一部分的歌。併的規則刻意保守
      （整段比、漢字不同就不准併、沒有證據就不猜）：錯併的代價是歌單裡混進別人
      的歌，比漏併嚴重得多。詳見 CHANGELOG 1.17.0。

### 多人包廂的秩序
- [x] 公平輪唱（新點的歌照「這是誰的第幾首」排，插播與手動拖曳照舊有效）*(2026-09-14)*
- [x] 每人的點歌上限 *(2026-09-15)* —— 「滿了之後怎麼辦」的答案是**別做成「今晚
      總共幾首」**：那種額度滿了就鎖到散場，只能等人去後台解鎖。改成「同時最多
      排幾首待唱」，排滿了等自己一首唱完就自動空出一格，機器講得出「什麼時候
      可以再點」，而且那個時間點馬上就到。詳見 CHANGELOG 1.13.0。

### 商用點歌機還有、這裡還沒有的（下輪可挑）
- [x] 包廂計時與「剩下多久」提醒 *(2026-09-16)* —— 「時間到之後怎麼辦」的答案是
      **不要停正在唱的那一首**：時間到讓它唱完，唱完之後不再播下一首，佇列
      一首都不刪。超時的上限因此是一首歌的長度（可預期），而不是停在副歌那一句
      （不可預期的難堪）。設定頁刻意沒有「立刻停掉」這個選項。詳見 CHANGELOG 1.14.0。
- [x] 舞台跑馬燈訊息 *(2026-09-17)* —— 「它會蓋住歌詞的哪一區」的答案是
      **一區都不蓋**：訊息帶做成版面裡的 flex 元素，出現時把整排 HUD 往下推，
      而不是絕對定位疊上去；歌詞與音準線那半邊完全不動。大字卡只在沒有人
      唱歌的時候出現，播歌中（連緊急訊息也）一律降級成上緣那一條。
      而且它**不捲動** —— 會動的字會一直把餘光拉過去，而唱歌的人正需要那個
      餘光看歌詞。詳見 CHANGELOG 1.15.0。
- [x] 歌名字數／注音首字查歌 *(2026-09-18)* —— 商用點歌機的實體鍵盤查法。
      「查什麼」的答案是**只查已經備好的曲庫**（列出來的每一首都是快取秒播），
      而難的不是鍵盤，是**索引要建在哪一串字上**：YouTube 標題不是歌名
      （「周杰倫 Jay Chou - 稻香 Rice Fields【Official MV】4K」照整串字算，
      字數是二十幾個、注音從「ㄓ」開始），所以先萃歌名本體再建索引；
      多音字則每個讀音都存 —— 只留一個的話，另一半使用者永遠查不到那首歌，
      而且他會以為曲庫裡沒有。詳見 CHANGELOG 1.16.0。
